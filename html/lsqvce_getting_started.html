Getting started with lsqvce

Three lines to a judged adjustment. Written for a first-time user; the binding details live in DATA_CONTRACT.md (data) and doc lsqvce.Options (what to do).

1. The three lines

opts = lsqvce.Options(Model="vce");     % what to do: one GLS solve ("gls"), or the
                                        % stochastic-model / variance-component loop ("vce")
R    = lsqvce.fit(data, opts);          % the one verb: your data struct -> a Results
R.report                                % the five-level verdict

That is the whole user surface: a plain data struct, an Options object, the verb fit, and a Results whose report tells you whether to believe the numbers.

2. Which kind of data do you have?

You haveThe data structEngine fit runs
A design matrix in memory, diagonal weights, no arc-wise unknowns data.A (m×u), data.l (m×1, observed minus computed), optional data.p (weights) adjust; Robust="irls" → robust
The same, but batched or nonlinear data.batchFcn, data.numUnknowns, data.numBatches; with data.x0 the callback returns the Jacobian at x adjust / robust / solveNonlinear
Days, arcs, arc-wise unknowns, coloured noise (GRACE-FO) data.common, data.days, data.systems(k) with your buildDay -- see below adjustBlock (gls), adjustVCE (vce, pooled), adjustVCEjoint (ellmer)

3. The streaming kind in one screen

data.common.commonParams = commonTbl;      % nc stated ONCE (or .numCommon)
data.days = 1:30;
s = struct();
s.buildDay         = @buildDayC;           % the one function you write
s.observationTypes = {'kbr','pos'};
s.covariance.kbr   = struct('type','arma','ar',[1 -1.6 0.9 -0.25],'ma',1,'sigma',1e-7);
s.covariance.pos   = struct('type','diag','sigma',0.02);
s.systemId         = 'C';
s.arcs             = @(day, obsType) arcSchedule('C', day);   % ragged: ids per day
s.localsPerArc     = 6;                    % fit numbers the local blocks for you
data.systems(1) = s;                       % add satellite D as data.systems(2)

buildDay returns, for one day and one observation type, a struct with A (m×nc), B (m×nl, may be sparse), l (observed minus computed), t (seconds), and optionally arcIdx / arcId for the arcs the day carries. Six rules keep you out of trouble:

  1. Deterministic. Same arguments, identical output -- the data is read twice per pass.
  2. Raw, not whitened. The toolbox whitens per arc from your covariance spec; the VCE loop reweights there.
  3. l is O − C, and t is in seconds.
  4. Arcs by id when ragged. A resolver in arcs plus arcId in the day; a missing id is a data gap.
  5. Local blocks from arcInfo. Fill B(rows, off + (1:k)); never compute an offset yourself.
  6. A stream called pos is 3-D by default. A scalar stream with that name needs ComponentsPerEpoch = struct('pos', 1).
Unknown struct fields are errors on purpose (lsqvce:fit:unknownField): a typo in a struct would otherwise be ignored silently. Every rule is checked before any data is read.

4. Reading the answer

R.report                 % level-0..4 verdict with actionable findings
R.coefficients()         % estimates, formal errors, 95 % bounds as a table
R.x, R.sigma0            % the estimate and the a-posteriori sigma0
R.history, R.noise       % the VCE trajectory and the converged noise model (vce/pooled/ellmer)
R.meta                   % provenance: version, release, UTC time, seeds, the options used

A sigma0 of NaN is a result, not a bug: the quadratic form cancelled catastrophically and the toolbox refuses to invent a plausible number (theory document, section 7).
