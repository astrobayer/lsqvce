lsqvce.engine.diagnoseAccum

Bridge a block-arrow lsqvce.engine.BlockAccumulator adjustment into LSQVCE diagnostics.

Syntax

[diagSol, batchFcn, nBatch] = LSQVCE.ENGINE.DIAGNOSEACCUM(acc, sol) returns exactly what

Description

lsqvce.engine.diagnose / lsqvce.engine.adjust expect:

diagSol   struct with fields {x, R, n, u, r, sigma0, s0sq, vPv, vPvSource, condR, condN, nBatch}
batchFcn  @(k) -> [A, l, p]   the k-th WHITENED batch, unit weight
nBatch    number of batches

so you can run the full five-level lsqvce verdict on a gravity-recovery adjustment built with the streaming accumulator + graceLoader:

[sol, tm, hist, acc] = iterateSeparable(cfg, satList, days);
[dsol, src, nB] = lsqvce.engine.diagnoseAccum(acc, sol);
D = lsqvce.engine.diagnose(dsol, src, 'nBatch', nB);
V = lsqvce.report(D);              % the five levels
S = lsqvce.engine.systematic(D);          % Ljung-Box / runs / covariate

WHY THE FULL PARAMETER SET, NOT THE REDUCED ONE ----------------------------------------------- lsqAccum pre-eliminates the local parameters per system by Schur complement and keeps only reduced common normals. lsqvce per-observation redundancy r_i = 1 - a_i' Qxx a_i is only correct if a_i and Qxx span the SAME parameter set the observation actually constrains -- i.e. the FULL set [common | all locals]. Diagnosing against the reduced common block alone would miscount the degrees of freedom the local parameters absorb and inflate every r_i. So this bridge rebuilds the full block-arrow system: columns are [x_common | y_sys1 | y_sys2 | ...], and each batch places its whitened A into the common columns and its whitened B into that system's local columns. The redundancy numbers this yields match lsqAccum's exact block-arrow leverage to 1e-16 (the two formulations are identical).

The whitening replays the loader's own Wfcn/Cfcn, batch by batch, with the same overlap discard as accumulation -- so the batches are bit-identical to what the accumulator saw. This is the 'verify' contract lsqvce checks.

Cost

---- diagSol carries the full R (u_full x u_full, u_full = nc + sum(nl)). For GRACE-FO with two satellites and a handful of local parameters each this is trivial; if the locals are per-arc and number in the thousands, R is large and you want lsqvce 'store','flagged' to bound memory.

REQUIRES acc constructed with 'KeepLocal', true (the default).
