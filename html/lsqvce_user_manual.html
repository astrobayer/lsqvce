User Manual — judging an adjustment, getting the stochastic model right

Version 5.0 (R5, 2026-09-03). This manual was written for lsqvce 4.x and is kept for its theory and interpretation content. The binding v5 authorities are DATA_CONTRACT.md (the data struct, priors, per-stream policy), RELEASE_NOTES.md (the v4 → v5 option map), doc lsqvce.Options (14 knobs + 5 groups, OnPass), and lsqvce_theory.pdf (the R5 theory: one accumulator, one estimator). Where this page names Model, GroupBy, adjustVCE, adjust, robust or the plot hooks, read the v5 successor from the map.

The full walk-through: the theory each diagnostic implements, what you supply, how to read the output, the gravity-recovery path, and a step-by-step recipe. New to the toolbox? The runnable version of the recipe is examples/demo_workflow.m; to pick an engine see Choosing an engine.

Part I — Theory

Notation follows Koch [3] and Teunissen [5]. Vectors are columns; is transpose; observations, parameters, redundancy. The compact equation set is in the Reference Manual; the essentials:

Gauss–Markov model and BLUE

The streaming accumulator forms by summing batch contributions and , so cost is memory and time, independent of .

QR versus the normal equations

Forming squares the condition number, . The remedy is to whiten () and solve by orthogonal triangularisation . The 'qr' backend accumulates batch by batch, keeping QR accuracy at normal-equation memory [11,12].

Residuals, redundancy, reliability

The trace identity is what Level 0 checks. Baarda’s w-test is the locally most powerful test for a single gross error; with unknown it becomes Pope’s tau [1,2]. The minimal detectable bias scales as : at nothing can be checked, and the undetected bias propagates into the parameters as [1,4,20]. Leverage is computed by back-substitution through the stored triangular factor, never the explicit inverse; the Hutchinson trace estimator [13] is used only for the large- variance-component path, where exactness is not needed.

Pope’s tau goes blind under contamination. It divides by , itself estimated from data that contain the blunders. At ~10% contamination a 100σ blunder can be undetectable, and iterating does not rescue it. Use a robust scale ('test','mad') and read the contamination gauge before trusting any tau.

Variance components

When several groups (GPS positions and KBR range-rates, or two satellites) enter one adjustment, their relative weighting is rarely known a priori. Helmert’s VCE estimates a factor per group, with , updates , and re-solves until the factors settle at unity. Only ratios are identifiable; one group fixes the gauge [6,7,3,9,10]. For in the thousands the trace is estimated matrix-free (lsqvce.engine.vceHutchinson (retired R5 M2)).

Block-arrow systems and coloured noise

Gravity recovery combines arcs sharing common parameters but each carrying local ones; ordering common-first gives a bordered block-diagonal (“arrow”) normal matrix, and each local block is eliminated by its Schur complement, leaving only the reduced system in core (full algebra in the Reference Manual §4). Coloured noise is whitened by an AR/VAR FIR recursion — a banded operator equal to the dense block-Cholesky GLS solve, never the dense matrix — and separable space×time covariance by a Kronecker whitener (§5). Orders are chosen by lsqvce.engine.selectArAcv and validated by Ljung–Box [14–17].

Part II — What you supply

A batch function batchFcn(k) returns the k-th batch:

Ank × udesign rows for this batch

Form of pInterpretation

Weights, not variances. . Passing silently inverts the weighting: your best observations are down-weighted and every downstream statistic is wrong while still looking plausible. It is dimensionally valid, so the toolbox cannot detect it.

The contract. Deterministic — batchFcn(k) is called twice (accumulate, then diagnose) and must return byte-identical data both times; a mismatch is an error, not a silent misattribution. Self-contained — a batch returns all of its own rows. Complete — every observation appears in exactly one batch, .

Part III — Reading the diagnosis

The report is ordered so a failure at one level invalidates the levels below. Read top to bottom, stop at the first red.

LevelQuestionKey output
0 · IntegrityDoes the arithmetic hold?, weights finite
1 · GlobalIs the model consistent? vs
2 · LocaliseWhere is it broken?data snooping, contamination gauge
3 · ReliabilityWhat can you not check?redundancy numbers, MDB, quadrants
4 · ParametersWhat do you actually know?correlations, conditioning

The Interpretation Guide covers the reliability quadrants and the contamination gauge in detail. What each tool adds: lsqvce.engine.systematic(D) tests residuals for structure a single-outlier search would miss; lsqvce.engine.snoop is iterative data snooping with the contamination guard; lsqvce.engine.robust is M-estimation for diffuse contamination; lsqvce.engine.vce/lsqvce.engine.varComp rebalance mis-weighted groups.

Part IV — Gravity recovery: the block-arrow path

The modern one-call front door is lsqvce.engine.adjustBlock (single GLS solve) and lsqvce.engine.adjustVCE (retired R5 M4: Model "vce" is a policy of the joint estimator) (the iterative SHAPE+SCALE loop). Build loaders with lsqvce.engine.makeLoader and hand them over:

% One-call block-arrow solve + five-level verdict
R = lsqvce.engine.adjustBlock({Lc, Ld}, days);   % loaders from makeLoader
R.report();

% Iterative: discover the noise model (SHAPE) and group weights (SCALE)
R = lsqvce.engine.adjustVCE({Lc, Ld}, days, ...
        'GroupBy', 'obsType', ...
        'Shape', struct('MaxOrder', 60, 'AcvTol', 1e-3), ...
        'Scale', struct('MaxIter', 8, 'Tol', 1e-3)).run();   % constructor-only since 2.0
R.report();
disp(R.history.sigma);        % per-pass variance components
Name-Value casing (WP-39, 2026-08-19). The public surface is migrating from inputParser to typed arguments signatures. The canonical option names are UpperCamelCase ('MaxIter', 'Backend', 'Verbose', …). Name matching itself remains case-insensitive (MATLAB name-value semantics, verified on CI), so legacy casings keep working — but the migrated functions (adjustVCEjoint, adjustBlock, iterateNoiseModel, and — on its deliberate inputParser pass-through — adjust so far) now enforce typed constraints, reject unknown option names, and match enum values such as "qr" case-sensitively in lowercase. Each function's help states its canonical names; the release notes list the break.

Under the hood these drive a lsqvce.engine.BlockAccumulator (kept reachable on R.acc for experts). The diagnostics bridge lsqvce.engine.diagnoseAccum rebuilds the full block-arrow system from the retained per-arc Schur factors to count the redundancy the local parameters absorb — without it the common-parameter redundancies (and every reliability number) are inflated.

Block-arrow traps. (1) Diagnose through the bridge, never the reduced common system alone. (2) VCE identifies only ratios — fix one group. (3) An arc whose local block is near-singular (too few observations to determine its own state) poisons the Schur complement; the accumulator flags it rather than silently absorbing it into the field.

Part IV-B — The interface you write

Part II describes batchFcn, the seam for the flat path (lsqvce.engine.adjust (retired R5 M5: the one accumulator)). The block-arrow path has a different seam: you write a day builder and hand it to lsqvce.engine.makeLoader. Everything else — arc slicing, whitening, the Schur complement, the VCE loop — is the toolbox's job. This part is what to write and, more usefully, what breaks when you get it subtly wrong.

Start from template/lsqvce_template.m, which is this part in runnable form.

The four things you write

#WhatRequired?
1buildDay — one day of one observation typealways
2the loader declaration — streams, system identity, a-priori covariancealways
3epochCov — the fixed per-epoch covariance Dmulti-axis streams only
4plot hooksnever (diagnostics)

1 · buildDay: the data seam

function D = myBuildDay(day, obsType, common, local, procOpt)
    D.A      = ...;   % m x nc   common design matrix for the WHOLE day
    D.B      = ...;   % m x nl   local design matrix (may be sparse)
    D.l      = ...;   % m x 1    observations
    D.t      = ...;   % m x 1    epoch timestamps [s]
    D.arcIdx = ...;   % 1 x nArc cell of row-index vectors (optional)
    D.nAxis  = 3;     % axes per epoch; omit for scalar streams
end

The full field table lives on the makeLoader page. Two things about it are worth saying here because they are not obvious from a field list.

You return a whole day, not an arc. The accumulator slices arcs out of what you return, using .arcIdx. If you omit .arcIdx the whole day becomes one arc — which is correct for a single continuous pass and wrong for a day that really contains several, because one local block will then be asked to describe several disjoint states.

Two arities are accepted. buildDay(day, obsType) is enough when your builder already knows its own parametrisation. buildDay(day, obsType, common, local, procOpt) receives the parametrisation tables and your configuration. makeLoader calls your function with as many arguments as it declares, so both keep working. Prefer the five-argument form: it is what lets you read nc = size(common,1) instead of hardcoding it, and it is the only form that receives procOpt.

2 · The loader declaration

L = lsqvce.engine.makeLoader(@myBuildDay, ...
        'observationTypes',  {'pos','rr'}, ...
        'covariance',        cov, ...
        'systemId',          'C', ...
        'arcs',              2, ...
        'days',              procOpt.days, ...
        'commonParams',      commonTable, ...
        'localParams',       localTable, ...
        'processingOptions', procOpt);

observationTypes are your streams, and they are the unit of variance-component estimation under 'GroupBy', 'obsType'. Name them after what they physically are, not after the file they came from: the name will appear in every diagnostic you read for the rest of the run.

When two satellites must share one system. Merge them whenever an observation's design couples both satellites' local parameters — an inter-satellite range or range-rate does exactly this. The block-arrow model has one local block per system, so a coupling observation cannot span two of them; give both satellites' streams the same system and stack their locals. Streams that are merely correlated do not need merging; that is what the variance components are for.
systemId must be numeric or a single char. The accumulator indexes systems by [store.sysID], and a multi-char string flattens into separate elements there. Carry a readable label in 'name' instead.

nc and nl are derived from the row counts of commonParams and localParams. There is no nc argument on any entry point: the count is stated once, where the parametrisation is defined, so it cannot drift.

3 · epochCov: the spatial half of a separable model

For a multi-axis stream the covariance is C = sigma^2 · D (R_t ⊗ I_d) D, where D is known per epoch — from a PPP solution, say — and R_t is the temporal law the toolbox estimates. Supplying D lets the temporal law be recovered by exact de-scaling rather than from whitened residuals. Scalar streams do not need this hook at all.

4 · Plot hooks (optional)

A hook is a handle you write, @(ctx) -> figureHandle. It only builds a figure; the engine owns show, export and close. A hook that throws is logged and skipped, so a broken plot never breaks a solve. postSolve fires after each solve; postModel fires once after the stochastic model is fitted, and only then does ctx carry the spectrum (.psd, .psdFreq, .acv, .arOrder). The ctx schema is versioned: fields are added, never renamed.

Hooks attach at construction. Passing a bare handle to makeLoader broadcasts it to every observation type. Assigning L.plotPostSolve after the loader exists requires a containers.Map keyed by obsType — the engine skips anything else silently.

Part IV-C — Four ways to get it wrong

Two of these the toolbox catches for you. Two it cannot, and those are the ones worth memorising.

Wrong Ⅰ — a builder that is not deterministic

% WRONG -- fresh noise on every call
function D = myBuildDay(day, obsType)
    D.l = readObs(day) + 0.01*randn(m,1);
end

% RIGHT -- seed from (day, obsType), or do not add noise at all
function D = myBuildDay(day, obsType)
    rng(day*1000 + double(obsType(1)));
    D.l = readObs(day) + 0.01*randn(m,1);
end

How you notice: you do not, from the numbers alone. The accumulator reads every day a second time for the residual pass; if the data differs, residuals are attributed to the wrong observations while every statistic still looks plausible. The same hazard applies to a file that is being rewritten while the run is in progress.

Wrong Ⅱ — axis-major row order

% WRONG -- all x, then all y, then all z
D.A = [Ax; Ay; Az];

% RIGHT -- epoch-major: [x1 y1 z1 | x2 y2 z2 | ...]
D.A = reshape([Ax'; Ay'; Az'], nc, [])';
This is the silent one. The temporal correlation model strides by nAxis. Stored axis-major, your time law is stretched by the axis count: a correlation length of 60 epochs is read as 180. The fit succeeds, the AR order looks sensible, the variance factors converge — and the stochastic model is wrong. Nothing errors. Check the row order first whenever a multi-axis stream will not whiten.

Wrong Ⅲ — passing variances where weights are expected

The flat path's p is a weight, not a variance. Passing sigma^2 instead of 1/sigma^2 silently inverts the weighting: your best observations are down-weighted. It is dimensionally valid, so the toolbox cannot detect it. This is the same trap Part II flags, restated here because it survives the move to the block-arrow path in the form of an inverted 'covariance' spec.

Wrong Ⅳ — mismatched row counts

D.A = zeros(m, nc);   D.l = zeros(m+1, 1);   % A and l disagree

How you notice: immediately, and by name. lsqvce:makeLoader:dayShape reports the day and obsType. Its sibling lsqvce:makeLoader:badDay fires when a required field is missing. These two are the reason a shape error never reaches the solver.

A checklist for a stream that will not whiten

  1. Row order — epoch-major? (Wrong Ⅱ: silent, and the most common cause.)
  2. Arcs — is .arcIdx really splitting the day, or did you inherit the whole-day default?
  3. AR order — is the fit hitting MaxOrder? Read R.summary(); a stream pinned at the ceiling needs a higher one, or ARMA.
  4. Grouping — does each variance-component group have enough redundancy? Oscillating variance factors in R.convergence() mean it does not; coarsen GroupBy.
  5. Determinism — re-run and compare. Different numbers from the same input means Wrong Ⅰ.

Part V — Step-by-step

A · Flat adjustment (single system)

  1. Wrap your data as a batch function. Decide the batching (by arc, day, file); make batchFcn(k) return [A,l,p]. Keep it deterministic.
  2. Get the weights right. . For coloured noise pass a covariance-model struct instead of a vector and let lsqvce whiten.
  3. Solve and judge in one call. [sol, D, V] = lsqvce.engine.adjust(u, batchFcn, nBatch);
  4. Read the report top-down. Stop at the first red. A Level 0 red is a data/weighting bug, not a blunder — fix it before reading on.
  5. If Level 1 fails, localise before rejecting. Run lsqvce.engine.systematic(D) first: a structured error is a model defect, and snooping it away mutilates good data.
  6. Snoop, gauge open. [sol,D,REJ] = lsqvce.engine.snoop(sol, D, batchFcn, 'test','mad');
  7. Before believing the parameters, read reliability. Check MDB and the quadrants for every parameter you care about. A clean residual at proves nothing.

B · Gravity recovery (many arcs, VCE)

  1. Write one makeLoader loader per satellite/arc returning whitened batches; give the common count nc and per-system numLocal.
  2. For a single solve call lsqvce.engine.adjustBlock; to discover the noise model and group weights, use lsqvce.engine.adjustVCE (retired R5 M4: Model "vce" is a policy of the joint estimator) with the constructor groups 'GroupBy', 'Shape', 'Scale' and run() (or, through the user front door, lsqvce.fit(data, lsqvce.Options(Model="vce"))).
  3. Inspect R.history.sigma for a group being systematically up- or down-weighted, and confirm convergence.
  4. Trust the field only where it is checked. Map the common-parameter redundancies; regions carried by a single arc are blind spots regardless of how small their residuals are.
Validate your build. results = run_all_lsqvce(); runs the whole suite. The Python mirrors under validation/ reproduce the numerical properties the MATLAB tests assert (redundancy identity, whitening equals dense GLS, ACV round-trip).
