lsqvce

Judging a least-squares adjustment — and getting its stochastic model right — in batches.
What lsqvce is. One flat package that merges two lineages: a streaming block-arrow accumulator with per-arc variance component estimation (for gravity-field recovery), and a per-observation diagnostics layer (redundancy numbers, the five-level verdict, data snooping, robust reweighting, systematic-error tests). The bridge diagnoseAccum runs the full verdict on a gravity-recovery adjustment.

Getting started

Everything is streaming: A and P are supplied in batches and nothing of size n is ever formed. Cost is O(u²·nk) time and O(u² + nk) memory per batch.

% batchFcn(k) returns the k-th batch: A (nk x u), l (nk x 1), p (nk x 1)
src = @(k) deal(A(idx{k},:), l(idx{k}), p(idx{k}));

[sol, D, V] = adjust(u, src, numel(idx));

if ~strcmp(V.verdict, 'PASS')
    systematic(D);                        % smooth error?
    [sol, D, REJ] = snoop(sol, D, src);   % iterative rejection
end
batchFcn is called twice — once to accumulate, once to diagnose — and must return identical data both times. This is checked; a mismatch is an error, not a silent misattribution.
Not sure which front door to use? See Choosing an engine & VCE backend — a decision flowchart (adjust / adjustBlock / adjustVCE) plus the exact-vs-Hutchinson cost curves. The runnable build-your-own-case guide is examples/demo_workflow.m.
Starting your own case? Copy template/lsqvce_template.m and fill in its two documented stubs. The GRACE-FO example (examples/demo_grace_dataLoader.m) is a worked case to read alongside it.

Gravity recovery workflow

% streaming block-arrow accumulate -> solve -> variance components -> verdict
acc = BlockAccumulator(nc, 'Backend','qr', 'KeepLocal',true);
acc.addSystem('GRACE-C', nl, graceLoaderC, days);
acc.addSystem('GRACE-D', nl, graceLoaderD, days);

vc  = vce(@(sig) buildAccumulator(cfg,sig), 'GroupBy','obsType');
sol = vc.sol;                                   % solution at converged weights

[dsol, src, nB] = diagnoseAccum(acc, sol);   % bridge to diagnostics
D = diagnose(dsol, src, 'nBatch', nB);
V = report(D);                           % the five levels

The five levels of the report

The report is ordered so that a failure at one level invalidates the levels below it.

LevelQuestionKey output
0 IntegrityDoes the arithmetic hold? sum(r_i) == n-u
1 GlobalIs the model consistent? s0²/σ0² vs χ²
2 LocaliseWhere is it broken? data snooping, contamination gauge
3 ReliabilityWhat can you not check? redundancy numbers, MDB, quadrants
4 ParametersWhat do you actually know? correlations, conditioning
Two hazards this toolbox exists to catch.

1. Pope's tau goes blind under contamination. It divides by s0, which is estimated from data that contain the blunders. At 10% contamination a 100σ blunder is undetectable, and iterating does not rescue it. Use 'test','mad', and heed the contamination gauge.

2. A small residual is not evidence of a good observation. A residual reveals only the fraction r_i of any error present (E[Δv] = −r·b, exactly). At r = 0 a 40σ blunder produces |w| = 0.000. Read the quadrants, not w alone.

Tests

run_all_lsqvce                    % THE gate: all 18 suites + a full log
run_lsqvce                        % one suite, interactively
Use run_all_lsqvce, not runtests('tests'). runtests on a folder SKIPS a file that fails to load and still reports the remainder as green — a suite can look clean while an entire file never ran. run_all_lsqvce counts load failures as failures and writes tests/last_run_all.txt.
