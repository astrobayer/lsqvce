lsqvce

Judging a least-squares adjustment — and getting its stochastic model right — in batches.
What lsqvce is. One flat package that merges two lineages: a streaming block-arrow accumulator with per-arc variance component estimation (for gravity-field recovery), and a per-observation diagnostics layer (redundancy numbers, the five-level verdict, data snooping, robust reweighting, systematic-error tests). One engine unit, lsqvce.engine.verdict, judges every fit; the user reaches it through R.report, R.systematic, R.snoop, R.reliability and R.ellipse.

Getting started

Everything is streaming: A and P are supplied in batches and nothing of size n is ever formed. Cost is O(u²·nk) time and O(u² + nk) memory per batch.

% batchFcn(k) returns the k-th batch: A (nk x u), l (nk x 1), p (nk x 1)
src = @(k) deal(A(idx{k},:), l(idx{k}), p(idx{k}));

R = lsqvce.fit(struct('batchFcn', src, 'numUnknowns', u, 'numBatches', numel(idx)));
V = R.report();

if ~strcmp(V.verdict, 'PASS')
    R.diag.flagIdx                        % which observations were flagged
    R.plot("residuals")                   % and what they look like
end
batchFcn is called twice — once to accumulate, once to diagnose — and must return identical data both times. This is checked; a mismatch is an error, not a silent misattribution.
Not sure which front door to use? There is only one: lsqvce.fit reads the KIND from the shape of your data struct. The API reference is the binding specification; the runnable build-your-own-case guide is examples/demo_workflow.m.
New to lsqvce? Run demo_tutorial and read the Manual's chapters Key concepts and Your first adjustment beside it: a complete streaming run in one file, with a buildDay and a prepareDay you can replace by your own reader.
Starting your own case? Copy examples/demo_tutorial.m for a streaming case, or examples/demo_fit.m for the user path (a plain data struct through lsqvce.fit). Two other starting points exist for narrower jobs: template/lsqvce_template.m is the ENGINE-tier Loader skeleton with one documented stub (myBuildDay), and template/gravfire_data.m maps a GRAVFIRE preprocessing bundle onto the declaration. The GRACE-FO example (examples/demo_grace_dataLoader.m) is a worked case to read alongside any of them.

Gravity recovery workflow

% one system per satellite pair: its streams share the day's orbit integration
s.prepareDay = @prepareGracePair;      % P = prepareGracePair(day, common, local, procOpt, info)
s.buildDay   = @buildDayGracePair;     % reads procOpt.prepared, returns one cell per arc
s.covariance.posC = struct('type', 'diag', 'sigma', 0.02);
s.covariance.posD = struct('type', 'diag', 'sigma', 0.02);
s.covariance.kbr  = struct('type', 'diag', 'sigma', 1e-7);
s.arcs = @(day, obsType) arcSchedule(day);
s.localParams = localTemplates;        % initial states, KBR empiricals, ACC per day
data.commonParams = [repmat({'common'}, nc, 1), shTable];
data.days = 1:31;   data.systems = s;

R = lsqvce.fit(data, Estimate="noise", Seed=1);   % accumulate, solve, estimate the noise
V = R.report();                                   % the five levels
R.plot("psd");                                    % the estimated spectra

The Manual, chapter Declaring your problem, writes this declaration out in full; template/kbr_variational.m is a runnable builder of this shape for Level-1B data.

The five levels of the report

The report is ordered so that a failure at one level invalidates the levels below it.

LevelQuestionKey output
0 IntegrityDoes the arithmetic hold? sum(r_i) == n-u
1 GlobalIs the model consistent? s0²/σ0² vs χ²
2 LocaliseWhere is it broken? data snooping, contamination gauge
3 ReliabilityWhat can you not check? redundancy numbers, MDB, quadrants
4 ParametersWhat do you actually know? correlations, conditioning
Two hazards this toolbox exists to catch.

1. Pope's tau goes blind under contamination. It divides by s0, which is estimated from data that contain the blunders. At 10% contamination a 100σ blunder is undetectable, and iterating does not rescue it. Use Diagnostics=struct('Test', "mad"), and heed the contamination gauge.

2. A small residual is not evidence of a good observation. A residual reveals only the fraction r_i of any error present (E[Δv] = −r·b, exactly). At r = 0 a 40σ blunder produces |w| = 0.000. Read the quadrants, not w alone.

Tests

cd('dev/tests'); ci_gate          % THE gate: every suite + a full log, or an error
run_lsqvce                        % one suite, interactively (from dev/tests)
Use ci_gate, not runtests('dev/tests'). runtests on a folder SKIPS a file that fails to load and still reports the remainder as green — a suite can look clean while an entire file never ran. The gate counts load failures as failures and writes its log under dev/tests.
