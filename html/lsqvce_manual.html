1 Purpose

lsqvce is a MATLAB toolbox for least-squares adjustment with variance component estimation. It was built for satellite gravity recovery (GRACE / GRACE-FO), where millions of correlated observations from several instruments determine a few thousand common parameters together with many arc-wise and day-wise local parameters, and it works just as well on a levelling network or a curve fit.

1.1 What it does

  • Adjusts a linear or linearised Gauss–Markov model. The common parameters are shared by all data; local parameters belong to one arc, one day or one system and are eliminated on the fly, so the full design matrix is never formed.
  • Estimates the stochastic model of every observation stream from the data: the spectral shape of its noise, its level, and a variance factor per arc (Estimate = "noise").
  • Regularises by declaration. A prior — a Kaula rule, minimum constraints, a background model — is a group of pseudo-observations in your columns; it carries a redundancy and can have its weight estimated.
  • Judges the result. Global test, outlier tests, redundancy numbers, minimal detectable biases, whiteness of every stream, reduced to a verdict by R.report.
  • Is robust on request: M-estimation with Huber, IGG3 or bisquare weights, and damped Gauss–Newton for nonlinear models, on the same loop.
  • Lets you watch: a hook after every pass, and one plot per question afterwards.

1.2 The three lines

lsqvce_setup                                   % once
R = lsqvce.fit(data, Estimate="noise");        % the one verb
R.report                                       % the verdict

data is a plain struct that describes your problem; the options say how to run it; R is everything that comes back.

3 The workflow, step by step

This chapter walks once through a complete adjustment. Each step names the chapter that treats it in depth. examples/demo_workflow.m is the same path as a script to run section by section.

3.1 Step 1 — Decide which kind of problem you have

your problem kind you supply
the design matrix fits in memory, one block of unknowns matrices data.A, data.l, data.p
too large for memory, or nonlinear, one block of unknowns batched data.batchFcn, data.numBatches, data.numUnknowns (or data.x0)
data arrive per day and arc, several instruments, nuisance parameters per arc or day, correlated noise streaming data.commonParams, data.days, data.systems with your buildDay

The first two are complete after one line:

data = struct('A', A, 'l', l, 'p', 1 ./ sigma.^2);     % weights, not sigmas
R = lsqvce.fit(data);
R.report

The rest of this chapter is the streaming kind, the one the toolbox is built for.

3.2 Step 2 — List the parameters

Write two tables. data.commonParams holds the parameters every observation can see (for gravity recovery: the spherical-harmonic coefficients); localParams of a system holds the nuisance parameters that live on one arc, one day or the whole system (initial states, accelerometer calibration, empirical terms). Column 1 of every row says how often it is instantiated; the remaining columns are yours:

data.commonParams = [repmat({'common'}, nc, 1), myCoefficientNames];   % nc rows
s.localParams = [ {'arc', 'bias'}; {'arc', 'drift'}; {'day', 'accScale'} ];

The toolbox derives every count and every column position from these tables. See Declaring your problem.

3.3 Step 3 — Write buildDay

One function returns the data of one day and one observation type, one cell per arc:

function D = myBuildDay(day, obsType, common, ~, procOpt)
    arcs = readMyArcs(procOpt.dataDir, day, obsType);   % your reader, deterministic
    n = numel(arcs);
    D = struct('A', {cell(1, n)}, 'B', {cell(1, n)}, 'l', {cell(1, n)}, 't', {cell(1, n)});
    for a = 1:n
        m = numel(arcs(a).omc);
        D.A{a} = myPartials(arcs(a), common);   % m x nc
        D.B{a} = zeros(m, 0);                   % no local parameters in this sketch
        D.l{a} = arcs(a).omc;                   % observed minus computed
        D.t{a} = arcs(a).tSeconds;              % epochs in seconds
    end
end

Return raw, unwhitened rows; never scale them by your weights. With local parameters, add a 6th argument info and place every column by its offsets (Declaring your problem).

3.4 Step 4 — Declare the system and its noise

s = struct();
s.buildDay = @myBuildDay;
s.covariance.range = struct('type', 'diag', 'sigma', 2e-7);   % white noise, level 2e-7
s.processingOptions = struct('dataDir', '/data/mission');
data.days = 1:30;
data.systems = s;

The fieldnames of covariance are your observation types. Start with a diag law and a realistic level; the estimator can find the colour (Choosing the stochastic model).

3.5 Step 5 — First run: one solve under the declared model

R = lsqvce.fit(data);          % Estimate = "none"
R.report

Check two things before anything else: that the run completes without a declaration error (every error names the field at fault), and that R.sigma0 is plausible. A σ₀ far from 1 means the declared accuracies are wrong in scale — fix that before estimating anything on top of it.

3.6 Step 6 — Estimate the stochastic model

opts = lsqvce.Options(Estimate="noise", Pool="stream", Seed=1);
R = lsqvce.fit(data, opts);
R.report
R.plot("psd"); R.plot("convergence");

The loop re-solves until the noise laws settle. Pool decides which streams share one spectral shape; ArcFactors (default on) gives every arc its own variance factor; Seed makes the probe-based redundancies reproducible.

3.7 Step 7 — Add regularisation if the problem needs it

A free network needs a datum; a high-degree gravity field needs a Kaula rule. Both are declared as priors in your columns:

data.priors(1) = struct('group', '^C|^S', 'x0', 0, 'sigma', 1e-10, 'estimate', "scale");

See Priors and regularisation.

3.8 Step 8 — Read the report and act on it

R.report prints a verdict and the evidence behind it: the global test, flagged observations, the reliability, the whiteness of every stream. Each adverse verdict has a standard next step — snooping, a richer noise law, a functional model correction. See Reading the results and the report.

3.9 Step 9 — Take the results out

T = R.coefficients();                  % estimates, formal errors, confidence bounds
[C, L] = R.toTable(data);              % your own tables with estimates written in
save('run.mat', 'R');                  % R.meta records version, seeds and options

4 Declaring your problem

This chapter shows how to map a real problem onto the data struct. The field-by-field contract — every field, its type, its default and every error — is in the API reference (chapters The data struct and buildDay).

4.1 The picture

You describe one adjustment with three answers: what is estimated for everybody (data.commonParams), which days are processed (data.days), and which systems deliver data (data.systems, one entry per satellite, receiver or instrument). Each system points to one function you write, buildDay, that returns the design rows and observations of one day for one observation type. Everything else — reading the days in order, whitening every arc with its noise law, eliminating the local parameters, iterating the variance components — is done by the toolbox.

The design is block-arrow shaped: every arc sees the common parameters through its A and its own local parameters through its B. The local blocks are eliminated arc by arc, so the memory need is set by the number of common parameters, not by the number of observations.

4.2 Choosing the scope of each parameter

Ask of every parameter: over what span is it constant?

constant over … table token examples
the whole adjustment, seen by all systems commonParams 'common' gravity-field coefficients, station coordinates
one calendar day, seen by all systems commonParams 'day' daily common terms
one arc of one system localParams 'arc' initial position and velocity, per-arc biases
one day of one system localParams 'day' accelerometer scale and bias
the whole adjustment, one system localParams 'system' antenna offsets, instrument constants

Rows are templates: the toolbox instantiates every row once per scope and derives the column counts. With data.paramColumns a row can also carry a validity interval and is then instantiated only on the days it covers — a one-day manoeuvre parameter is just a row with a one-day validity.

4.3 Writing buildDay with local parameters

Declare the 6th argument and never compute a column offset yourself:

function D = buildDayGrace(day, obsType, common, ~, procOpt, info)
    raw  = readGraceDay(procOpt.dataDir, day, obsType);  % your reader, deterministic
    nArc = numel(info.arcId);                            % the schedule's arcs, in order
    D = struct('A', {cell(1, nArc)}, 'B', {cell(1, nArc)}, ...
               'l', {cell(1, nArc)}, 't', {cell(1, nArc)});
    for a = 1:nArc
        arc = raw.arc(a);                                % empty on a data gap
        D.A{a} = shPartials(arc, common);                % m_a x info.nc
        D.l{a} = arc.observed - arc.computed;            % observed minus computed
        D.t{a} = arc.tSeconds;
        B = sparse(numel(D.l{a}), info.nl);
        B(:, info.offsetOf(info.arcId(a)) + (1:info.count(a))) = arcPartials(arc);
        if info.dayCount > 0                             % this day's 'day' block
            B(:, info.dayOffset + (1:info.dayCount)) = accPartials(arc);
        end
        D.B{a} = B;
    end
end

B may be sparse; it usually is, because an arc touches only its own block.

4.4 Arcs and schedules

The cells buildDay returns are the arcs of the day. Without an arcs field the toolbox takes them as they come, and days may differ in their number of arcs. Declare a schedule only when 'arc' parameters need to be counted before any data is read:

s.arcs = 4;                                  % arcs 1..4 on every day
s.arcs = @(day, obsType) arcTable{day};      % a resolver for ragged schedules

A data gap is an empty cell; a day without any data in a system belongs off that system’s calendar (s.days).

4.5 Several systems

Each satellite or instrument is one entry of data.systems, with its own buildDay, covariance specs, local parameters and calendar. Systems share only the common parameters. An observation that depends on the local parameters of two satellites — the range-rate between two GRACE spacecraft — belongs to one system whose local table holds both satellites’ parameters. One reader for several setups takes the setup as data: plain values in processingOptions, its 5th argument, or a closure that binds a configuration (API reference, chapter buildDay, Where the handle goes).

When several streams of that system rest on one expensive computation — the orbits of both satellites and their partials for the whole day, used by the kinematic orbits and by the range-rates — put it in the system’s prepareDay. It runs once per build of a day, before the first stream of the day is built, and every buildDay of that day finds its result in procOpt.prepared (API reference, chapter buildDay, What all streams of a day share; template/kbr_variational.m does exactly this).

4.6 Multi-axis observations and their accuracy

A stream with several axes per epoch — a kinematic orbit, a gradiometer — is returned epoch-major (x₁ y₁ z₁ x₂ …). What the preprocessing knows about the accuracy of every epoch travels with the day as D.Cep, one cell per arc:

D.Cep{a} = sigmaPerEpoch;                                % n x 1   scalar stream
D.Cep{a} = [sx sy sz];                                   % n x 3   per-axis sigmas
D.Cep{a} = permute(reshape(Q.', 3, 3, []), [3 1 2]);     % n x 3 x 3 full covariance

The vector forms are standard deviations and the matrix form is a covariance — check one epoch by hand before a campaign. Cep is relative to the sigma of the covariance spec: declare sigma = 1 when Cep already carries the absolute accuracy.

4.7 A complete declaration: two GRACE-FO satellites

data.commonParams = [repmat({'common'}, nSh, 1), shParameterTable(60)];
data.days = 1:31;
cov.kbr = struct('type', 'arma', 'ar', [1 -1.6 0.9 -0.25], 'ma', 1, 'sigma', 1e-7);
cov.pos = struct('type', 'diag', 'sigma', 0.02);

s = struct();
s.buildDay = @buildDayGrace;
s.covariance = cov;
s.id = 'C';  s.name = 'GRACE-FO C';
s.arcs = @(day, obsType) arcSchedule('C', day);            % 'arc' rows need a schedule
s.localParams = [ ...
    [repmat({'arc'}, 6, 1), {'x0'; 'y0'; 'z0'; 'vx0'; 'vy0'; 'vz0'}];   % initial state
    {'arc', 'kbrBias'; 'arc', 'kbrCos1cpr'};                           % KBR empiricals
    [repmat({'day'}, 3, 1), {'accScale'; 'accBias'; 'accDrift'}]];     % ACC per day
s.processingOptions = struct('dataDir', '/data/gracefo');
data.systems(1) = s;
s.id = 'D';  s.name = 'GRACE-FO D';  s.arcs = @(day, obsType) arcSchedule('D', day);
data.systems(2) = s;

R = lsqvce.fit(data, Estimate="noise", Pool="stream", ArcFactors=false);
R.report

A runnable builder of this shape for real Level-1B data is template/kbr_variational.m (chapter The examples).

4.8 Checklist before the first run

  • buildDay returns A, B, l, t as one cell per arc, each arc with one row count; l is observed minus computed; nothing is whitened.
  • Calling buildDay twice with the same arguments gives identical output.
  • t is in seconds.
  • size(A, 2) equals the derived nc, size(B, 2) the derived nl — build them from info.nc / info.nl and place blocks by the info offsets.
  • Every observation type is a field of covariance.
  • Cep, if given, has one cell per arc and matches the rows (n·d = m).
  • No unknown field names in data: a typo is an error on purpose.

5 Choosing the stochastic model

The weights of a least-squares solution are the inverse of the noise covariance. This chapter says what to declare, what to let the data estimate, and how to read the estimate back. The laws and their fields are listed in the API reference (Covariance specifications); the mathematics is in the theory.

5.1 Three facts, three places

fact declared in estimated?
the temporal law — how the errors of a stream correlate from epoch to epoch covariance.<type>.type and its parameters yes, with Estimate = "noise"
the level of that law covariance.<type>.sigma (a standard deviation) yes
the per-epoch accuracy — what the preprocessing knows about each observation D.Cep, returned by buildDay never: it is data

The toolbox combines them per arc. A filter law (diag, arma, an AR-whitened psd, var) is applied in batches of up to 20 000 rows that overlap by the memory of the filter (for an arma law with an MA part, until its impulse response has decayed to rounding), so the batching does not change the result. A dense law (acf, custom, a psd whitened as Toeplitz) is factorised over the whole arc: exact, at a cost of O(m³) and m² memory for an arc of m rows — for arcs of many thousand epochs prefer a filter law. Above 20 000 epochs a dense law is refused (lsqvce:covModel:denseArcTooLong, 3.2 GB for the factor alone at that length); the field maxDenseArc on the covariance spec raises the limit deliberately. Under Estimate = "noise" the estimator’s sweep forms every arc’s covariance densely whatever the whitener, so there the same limit applies to every law, a filter law included.

5.2 What to declare

  • You do not know the colour of the noise. Declare type = 'diag' with a realistic sigma and run Estimate = "noise": the estimator starts from white noise and finds the spectral shape. Under estimate = "law" (the default) this is what happens to every stream, whatever law it declares: the declared law contributes only its sigma, as the starting level, and the shape is estimated from white noise. (For an arma law sigma is an innovation standard deviation; as a level it is read as the marginal one.)
  • You know the noise spectrum. Declare type = 'psd' with f and S, or an arma filter; set estimate = "scale" to keep the shape and estimate only the level, or "none" to use it as given.
  • Your axes are correlated in time across axes. Declare a var law (no Cep).
  • A stream you trust completely — a prior stream, a reference — takes estimate = "none".

5.3 Running the estimator

opts = lsqvce.Options(Estimate="noise", Pool="obsType", ArcFactors=true, ...
                      MaxPasses=7, Seed=1, Noise=struct('Grid', 120, 'Whitener', "ar"));
R = lsqvce.fit(data, opts);

Per pass the toolbox solves under the current laws, sweeps every arc once for its whitened residuals and their redundancies, and updates the spectral shape of every pool group, the level of every stream, the factor of every arc and the σ of every prior with estimate = "scale". It stops when no component changes by more than Tolerance — the σ of a prior group included, which is first updated on the pass after it enters the solve, so the loop does not stop before — or after MaxPasses. A spectral bin the data barely determine may change by more, in proportion to its own standard error (the next chapter, “When the loop did not settle”).

The choices that matter:

choice guidance
Pool streams of the same physics may share a shape ("obsType": both satellites’ range-rate); never pool streams of different physics or units — positions with range-rate drives the normal matrix towards singularity
ArcFactors on when arcs are numerous and long enough to carry their own variance; off for few or short arcs
Noise.Grid the spectral resolution of the estimated law; finer grids resolve narrow spectral features but give each bin less redundancy per pass. Keep 60 with the default Smooth = 1. Fewer bins cut the estimator’s variance too, but bias the level low when the spectrum has a sharp low-frequency peak (16 bins: −12 % at AR(0.98))
Noise.Whitener how every psd law — the estimated one and any you declare — whitens an arc: "ar" for long arcs (cost O(m·p) instead of O(m³) in the solve); "toeplitz" (the default, exact) when the spectrum has narrow features a low-order filter cannot follow. Under Estimate = "noise" "ar" saves the solve only — the sweep forms each arc’s covariance densely (above) — and the estimated spectrum is then whitened by an AR(30) that approximates it: exact enough for short-memory noise (an AR(1) law to about 1 %), biased where AR(30) cannot follow the shape (a 1/f floor: tens of percent per bin, and the loop need not settle)
Probes, Seed the redundancies are estimated with random probes: 100 probes are the standard; a fixed Seed makes the run reproducible

Run one pass with Estimate = "none" first. If σ₀ is near 1 the declared weights are consistent. A σ₀ far from 1 says the Cep scale is wrong — most often an information matrix used where a covariance was expected — and estimating a law on top will not fix it.

5.4 Reading the estimate

R.noise.stream           % the stream keys, in the order of model{}
R.noise.model{k}.sigma   % the estimated level of stream k
R.noise.Sgroups          % the estimated spectrum of each pool group
R.summary()              % one row per stream: level, whiteness
R.plot("psd")            % the spectra

The standard deviation of one arc is the product of three terms: the declared sigma, the square root of the arc factor, and R.sigma0. With sigma = 1 and a Cep carrying the absolute accuracy, that product reads directly as how much too optimistic the preprocessing’s covariance was on this arc.

After convergence the whitened residuals of every stream should be white. The loop tests that in every pass, per stream, with a Ljung–Box test over 20 lags at α = 0.05; the result is in R.summary() and R.history.white (it is not a stop criterion). It detects short-lag correlation, periodic terms and excess low-frequency noise; a correlation that exists only at one long lag (an echo, a repeat-track pattern) is invisible to it — test for that with R.systematic('Lags', L).

Three assumptions of the model can be contradicted by the data, and the loop checks them after convergence (R.noise.checks, one warning each):

warning what the data say what to do
lsqvce:adjustVCEjoint:poolNotWhite a stream of a pool group is not white under the group’s shared law. Either the group mixes spectra, which biases both levels and the formal errors, or the stream has something unmodelled in it (an event, a drift) compare Pool = "stream"; regroup, or find the event
lsqvce:adjustVCEjoint:levelVaries a stream’s arcs scatter far beyond their sampling error around one level: the level changes from arc to arc or day to day arc factors for that stream
lsqvce:adjustVCEjoint:memoryVsArc the estimated correlation time exceeds half the median arc: the arcs’ local parameters absorb the long memory, and the level comes out low (−12 % at a correlation time of 200 against 256-epoch arcs) longer arcs, or a law that models the low frequencies

The formal errors of an estimated noise model are plug-in: R.sol.Cxx treats the estimated covariance as known. On short or few arcs they are 3–13 % optimistic in σ; on long records the optimism is negligible.

Arcs can be skipped in a pass: gap (no data) or nonPD (the arc’s covariance is not positive definite — a mis-scaled Cep produces exactly this). A skipped arc keeps its previous factor; when more than Noise.SkipThreshold of a stream’s arcs are skipped, the pass is refused rather than estimated on a fraction of the data.

5.5 Outliers

Gross outliers belong to preprocessing. Inside the adjustment there are three tools:

  1. Arc factors down-weight a whole bad arc automatically (ArcFactors = true).
  2. Robust estimation down-weights single epochs: Robust = "igg3" or "bisquare" together with Estimate = "noise" weights every epoch of every stream inside the joint estimator, standardised by the stream’s own robust scale; a rejected epoch is removed from the arc exactly. Prefer a redescending function (igg3, bisquare) for gross blunders: Huber keeps part of their weight. The factors are in R.noise.robust.factor; a pass that rejects more than 45 % of the epochs warns that it has reached the breakdown point.
  3. Diagnose, then decide. Read the outlier tests in R.report, repair or remove the observations in buildDay and run again. Weights taken from a robust run can be made data: zero the rejected epochs’ rows and mark them excluded in the day buildDay returns — the toolbox deletes such rows from a correlated law exactly, whole epochs or single axes (removing them leaves a gap that a psd or arma law, which counts lags in samples, takes for one step — lsqvce:covModel:unevenGrid says so); store the weights, never recompute them inside buildDay.

With Estimate = "none", Robust runs a stand-alone iteratively re-weighted solve on the whitened innovations, with its own budget RobustOpts.

6 Priors and regularisation

6.1 The idea

A prior says “these parameters are observed to be x₀, with standard deviation σ”. It is written as pseudo-observations L·x = x₀ + v in your own columns, and the toolbox treats it as data: it enters the normal equations, it has a redundancy (how much of it the data overrule), and its σ can be estimated like the level of any other stream. Regularisation is therefore never an option on the run: it is a declared part of the problem. The fields are listed in the API reference (Priors).

6.2 Typical priors

A datum for a free network. Minimum constraints on the null space N of the design (L = Nᵀ, x0 = 0) fix the datum without distorting the solution. Declare the datum as a group of its own:

data.priors(1) = struct('L', Nnull.', 'x0', 0, 'sigma', 1, 'name', 'datum');

The solution and its covariance are the minimum-constraint ones for any σ, also when the datum is declared as several groups (for instance translation and rotation separately). The datum rows are constraints, not observations: the report does not count them as uncontrolled. Without a datum a rank-deficient system is refused by name; the toolbox never guesses one.

A Kaula rule on a gravity field. One group per rule, σ estimated:

data.priors(1) = struct('group', '^[CS]', 'x0', 0, 'sigma', 1e-10, 'estimate', "scale");

group is a regular expression on the name column of commonParams; the toolbox builds one row per matched coefficient. Relative weights inside a group (degree-dependent Kaula factors) go into an explicit L instead: divide each row by its own relative σ.

Calibration parameters of an instrument. Priors on local parameters sit on the system:

data.systems(k).priors(1) = struct('group', '^accScale', 'x0', 1, 'sigma', 0.02, ...
                                   'estimate', "scale");

The accelerometer scales of both satellites over a month form one group with many rows — exactly what makes their σ estimable. A group with one row cannot estimate its own σ.

6.3 Writing L yourself

lsqvce.layout(data) announces which column of A and B holds which template row on which day and arc, so an operator can be built by name:

lay = lsqvce.layout(data);
L = zeros(2, lay.nc);
L(1, lay.colCommon(5, [])) = 1;            % template row 5 of commonParams
L(2, lay.colCommon(6, [])) = 1;

examples/demo_priors.m builds priors both ways.

6.4 Reading the result

R.noise.priors and R.noise.priorHistory report the σ of every common group per pass; a local group appears as the stream prior_<name> of its system in R.noise.model. λ = σ₀²/σ² is the regularisation the data support. R.report counts the redundancy of the prior rows like that of any observation.

6.5 Activating a prior later

from = 3 activates a group in the third pass of an iterative run: the first passes then see the data alone. A single solve skips such a group with a warning.

What the numbers refer to.

  • Observations. An observation index is a row in sweep order: the arcs in the order they were accumulated, then the rows of a declared prior. Prior rows are counted in n and in the redundancy.
  • Units. On the streaming kind every row is whitened by its declared law before it is tested. v, w, r_i and the MDB therefore belong to whitened rows, and an MDB is in units of that row’s own sigma. For correlated data only sums such as sum(r_i) and vPv are the same in both frames.
  • Parameters. A parameter index in the report refers to the full parameter vector: the commons first (indices 1..numel(R.x)), then each system’s local parameters in block order. The u in the header counts both.
  • The a-priori sigma0. For whitened rows the a-priori sigma0 is 1. The report’s s0 is the a-posteriori value recomputed from the residual sweep and should match R.sigma0; Level 0 checks this.

7.6 Level 2 — LOCALISE (where is it broken?)

Level 2 locates individual bad observations by data snooping: one test per observation on its normalised residual

w_i = (P v)_i / (scale · sqrt((P Qvv P)_ii)).

The scale is the estimated s0 (Pope), the a-priori sigma0 (Baarda) or the robust MAD scale. With Bonferroni = true the level of each test is Alpha / n. The critical value follows the scale: Pope’s tau, the normal distribution, and for the MAD a Student t with r/2 degrees of freedom (calibrated to the nominal level; Pope’s tau there gave up to 60 times the nominal false alarms on small networks). The price of the valid level is power on short networks under heavy contamination: with 50 observations and 10 % blunders of 25 sigma, four or more of five are found in about 60 % of cases (snooping with Test="mad" does not change that); from about 200 observations all of them.

7.6.1 The contamination cross-check

Pope’s statistic divides by s0, and s0 is estimated from the same data that contain the blunders. A group of blunders therefore inflates the scale it is tested against, and the blunders mask each other. To catch this, the report compares s0 with a robust MAD scale of the raw standardised residuals and estimates the contaminated fraction fhat: the share of residuals beyond 2.5 robust sigmas. On clean data fhat sits near P(|Z| > 2.5) = 0.0124. As a backstop it also prints s0/sigma0, which contamination cannot suppress but which is only as good as your declared sigma0.

The null band is measured, for every n (the scored residuals): on clean data the count n·fhat is negative binomial with mean n · 0.0124 · (1 + 27/n) (a small sample’s MAD is biased low) and variance 1.69 times that mean. D.fhatTol is its 99.75 % point (false alarms ≤ 0.25 %), and fhat counts as collapsed only where it is implausibly low for clean data (P(K ≤ n·fhat) ≤ 1 %). Below n ≈ 450 even fhat = 0 is common on clean data (59 % at n = 30), so there a captured robust scale cannot be told from a sigma0 declared too small (D.collapseDetectable = false).

The cross-check appears whenever RobustCheck = true, whatever the Bonferroni setting. Exactly one of these lines is printed:

code severity condition action
SNOOP_SCALECHECK NOTE clean: fhat within its null band D.fhatTol s0 and the robust scale agree, so the flag list can be believed. (This line is omitted under Test = "mad".)
SNOOP_INDETERMINATE WARN fhat within its null band, s0/sigma0 > max(3, 2·(1 + 3/sqrt(2r))), and a collapse undetectable at this n Either sigma0 is declared too small (the common case: then the flag list can be believed) or more than half the data are bad and the robust scale is captured (then it cannot). SNOOP_MODERATE WARN fhat above the null band, below 0.10 Pope’s test is starting to lose power. Re-diagnose with Test = "mad", and reject one observation at a time (R.snoop(Test="mad")).

  • SNOOP_BACKSTOP (NOTE) appears whenever s0/sigma0 exceeds its clean-data tolerance 1 + 3/sqrt(2r). It is not printed in the breakdown and indeterminate cases, which already report the backstop. If your sigma0 is trustworthy, the residuals really are that much larger than promised.
  • SNOOP_MAD (NOTE) states that the robust scale replaced s0 (Test = "mad").

7.6.2 The snooping result

  • SNOOP_SETUP (NOTE) prints the test, Alpha, the corrected level, n, the critical value |w| > k and the number of false alarms expected by chance (Alpha under Bonferroni).
  • SNOOP_NOBONF (WARN) replaces it when Bonferroni = false. It prints the uncorrected level and roughly how many good observations will be flagged by chance. Set Bonferroni = true.
  • SNOOP_VACUOUS (ERROR, Pope only) appears when the critical value comes so close to the upper bound sqrt(r) of Pope’s statistic that a residual must carry at least 90 % of vPv to be flagged (k^2 / r >= 0.9, D.vacuityShare). Only a blunder that dominates the whole adjustment can then be found, and an empty list says nothing. Accept a weaker Alpha or a weaker family-wise correction, or accept that this network cannot detect its own blunders.
  • SNOOP_CLEAN (NOTE) means nothing exceeds the critical value. It prints the largest |w| and its observation index.
  • SNOOP_FLAGS (WARN) gives the number flagged, the number expected by chance, and so about how many are real. SNOOP_TABLE (NOTE) lists up to 15 of them, worst first, with columns obs, w, r_i, v, MDB. Read w and r_i together.
  • SNOOP_LOWR (WARN): some flagged observations have r_i < RWeak. A large residual on a weakly controlled observation may be error absorbed from a neighbour. Rejecting it is close to a coin flip; prefer to re-measure.
  • SNOOP_ITER (NOTE) prescribes the remedy. Reject one observation at a time (the largest |w|), re-solve and test again, because blunders mask each other and a single pass misses some of them:
[D2, REJ, sol2] = R.snoop();               % Pope, Bonferroni, one at a time
[D2, REJ, sol2] = R.snoop(Test="mad");     % under contamination
REJ.idx      % rejected, in order;  REJ.refused  % tripped but r_i < RMinReject (0.10)

R.snoop takes Test ("pope" or "mad"), Alpha and Bonferroni name-values; left out, they are R.diag’s, so Options.Diagnostics reaches them. It caps the number of rejections at max(10, 0.01·n) and stops at a fraction of 0.25 (MaxRejectFrac). It refuses to run at SNOOP_BREAKDOWN and SNOOP_REFUSE (Force = true proceeds with a warning), warns at SNOOP_INDETERMINATE (and at SNOOP_CONTAMINATED under Pope’s test), and tests only what R.diag tests (r_i > RMin). It refuses observations with r_i < RMinReject, re-solves cleanly over the survivors at the end, and leaves R unchanged. A prior’s rows, common or local, are never rejected, and the re-solve keeps the prior as a prior (a datum stays a datum); the re-diagnosis keeps R.diag’s thresholds and storage (Store, NWorst, RobustCheck). The returned D2 counts in the original observation numbers (D2.flagIdx, D2.rejectedIdx, …); its per-observation vectors cover the survivors, and D2.obsIdx names their original numbers. It cannot reject single rows of a correlated batch (lsqvce:snoop:correlatedBatch): there, remove the epoch in buildDay or use Robust.

7.7 Level 3 — RELIABILITY (what can you not check?)

Level 3 shows which observations the tests could not check at all.

  • REL_HEAD (NOTE) prints the smallest redundancy number and its observation, the mean redundancy r/n, and the MDB non-centrality delta0. delta0 is computed at the Bonferroni-corrected level and Beta: 4.13 at a level of 1e-3 with Beta = 0.2, and larger as n grows. It is the normal (Baarda, known-sigma) value. Under Test = "mad" the threshold is Student t with r/2 degrees of freedom, so the bias that can hide from that test is larger (about +50 % at n = 30, +25 % at n = 50, +6 % at n = 200); the line then says that the MDB, the envelope and the external reliability are the Baarda values.
  • REL_QUADRANTS (NOTE) counts the observations in each cell of the (|w|, r) table. |w| is high when it exceeds the critical value; r is low when it is below RWeak.
quadrant |w| r meaning
clean outlier high high reject with confidence
AMBIGUOUS high low could be a neighbour’s error; re-measure
verified low high tested, and passed
UNTESTED low low not “fine”: the test had no power

A residual shows only the fraction r_i of an error in its observation. A small |w| on a low-r observation is therefore no evidence of health. R.reliability() gives the same quadrant per observation; the rows of a datum prior carry the label "datum" and are not counted in any quadrant.

REL_SILENT WARN observations in the UNTESTED quadrant These observations did not pass the test; the test could not see them. Strengthen the geometry (more or better-placed observations), or validate them externally.
REL_AMBIGUOUS WARN flagged observations with r_i < RWeak Re-measure rather than reject.
REL_ENVELOPE NOTE always, when MDBs are finite The hidden-blunder envelope: the median, 90th and 99th percentile and the worst MDB, in units of each observation’s sigma. “Half of my observations could hide an undetected error larger than the median.” The percentiles come from a fixed-seed reservoir of 5000 samples.

External reliability (REL_EXTERNAL) answers one question: how far could the worst undetectable blunder (one MDB in the worst observation) move a parameter, in units of that parameter’s own sigma? The report names the observation and the parameter. ≤ 1.8 NOTE Normal for this size.

> 3 ERROR One observation carries far more leverage than the rest. Find it through the minimum r_i and the named observation, and do not trust the formal sigmas.

If the absolute value exceeds one sigma, the line adds that an undetectable blunder could move the parameter by more than its stated precision. When that happens at a normal ratio, the remedy is more observations, not a different estimator.

7.8 Level 4 — PARAMETERS (what do you actually know?)

Level 4 checks conditioning and correlations, and lists the parameter precisions.

  • PAR_COND (NOTE) prints cond(R) and cond(N). On the fit path these are lower bounds formed from the blocks of the cofactor (no SVD), and they are marked [LOWER BOUND]. The true conditioning can be worse than printed, never better, so the thresholds below are optimistic.
  • PAR_ILLCOND: WARN when cond(N) > 1e10, with roughly log10(cond(N)) of 16 digits lost. ERROR when cond(N) > 1e14: the printed sigmas are meaningless. Rescale the parameters so that the columns of the design have comparable norms, and use Backend = "qr", which avoids squaring the condition number. A rank defect (a free network) needs a datum, which you declare as a prior (chapter Priors and regularisation).
  • PAR_CORR reports the strongest correlation and its parameter pair. It is a NOTE at most 0.95, a WARN above 0.95 (nearly inseparable: use R.ellipse(i, j) rather than the individual sigmas), and an ERROR above 0.999. In the ERROR case only a combination of the two parameters is determined. Fix one of them, reparameterise to estimate the combination, or add observations that separate them.
  • PAR_TABLE (NOTE) lists the first 30 parameters of the full vector: x, the a-priori sigma (sigma0 · sqrt(Qxx_jj)) and the scaled sigma (s0 · sqrt(Qxx_jj)). The scaled column is what R.coefficients reports for the commons.
  • PAR_SCALE (WARN) appears when |s0²/sigma0² − 1| > 0.1, so that the two columns differ. Which column is honest depends on why the variance factor deviates. If the weights were wrong, the scaled column is right. If there are outliers or systematics, neither is right. Resolve Levels 1 and 2 before quoting either.

7.9 Beyond the report: the stochastic model

The report judges one solve under the final weights. Whether those weights describe the noise, stream by stream, is a separate question, and the report does not answer it. For an Estimate = "noise" run, read it from R.history, R.summary() and R.convergence().

7.9.1 Whiteness per stream

On every pass the loop tests the law-whitened residuals of each stream with a Ljung–Box test. The test pools over the stream’s arcs, uses K = 20 lags and calls a stream white when p > 0.05.

T = R.summary();             % stream | sigma | arOrder | white | pValue  (final pass)
T(~T.white, :)               % the streams that never whitened
R.history.streams            % stream keys 'satKey|obsType', the column order of
R.history.white(end, :)      %   these per-pass matrices (nPass x nStream)
R.history.whitePval(end, :)

In summary(), sigma is the stream’s level factor sqrt(mean arc factor). It is near 1 when the declared sigma was right, and it tells you by how much the declared sigma was off. arOrder is NaN, because the joint estimator fits a spectrum, not an AR order.

A stream that is not white has residual correlation that its law does not describe. Possible causes and remedies, roughly in order:

  1. The law was not estimated for it. If the stream’s covariance spec has estimate = "none" or "scale", the declared law is used unchanged (its R.noise.model{k}.C is then empty). Set estimate = "law" for that stream.
  2. It shares a law with streams that behave differently. Use a finer Pool ("obsType", or "stream" for one law per stream).
  3. The spectral grid is too coarse for its correlation: raise Noise.Grid.
  4. The functional model is incomplete. An unmodelled signal (a drift, a once-per-revolution term) appears as coloured noise. Run R.systematic(Covariates=struct('time', t, ...)): the binned-mean test points to the covariate. A correlation that lives only at a long lag (an echo, a repeat pattern) is invisible at K = 20; test it with R.systematic(Lags=L).

R.plot("psd") draws the estimated spectral shape of each pool group, and R.plot("residuals", Stream="...") draws a stream’s whitened residuals against time.

7.9.2 When the loop did not settle

The loop stops when two conditions hold. Every arc factor changed by at most Tolerance. Every spectral bin j changed by at most Tolerance·max(1, sqrt(200/r_j)), where r_j is the bin’s redundancy and sqrt(2/r_j) the relative standard error of its estimate. A bin with a redundancy of 200 or more is held to Tolerance. A bin with less, such as the zero-frequency bin that per-arc parameters absorb, may move further, in proportion to its own standard error: at the default Tolerance 1e-2, by a tenth of it. A finer step would ask for more precision than its estimate has. A smaller Tolerance tightens every bin. (Before 6.26.0 every bin was held to Tolerance. On the fixtures of the development record that took 14–168 passes, while the solution was already within 0.1–0.2 of its standard error of the end point after 10.)

Each pass records R.history.binRatio (the largest change of a bin divided by its bound, so ≤ 1 means every bin settled), R.history.levelDev, R.history.maxDev (the largest |α² − 1|, a reading) and R.history.xStep (the largest change of the solution since the pass before, in units of its own standard error). R.convergence() gives one row per pass with pass, maxSigmaOffset (the largest |sigma − 1| of the per-stream level factors: a reading, not the stop rule), nWhite, minWhitePval, converged, maxDev, levelDev, binRatio and xStep. R.convergence(Plot=true) and R.plot("convergence") draw the same record.

With stopReason = "maxPasses", the warning names the bins that still move, with their redundancy against the median of their group, and the solution’s last step:

  • If xStep is a few hundredths or less, the solution has settled to well within its errors, and the bins that still move are ones the data barely determine.
  • If binRatio is still falling, the loop needs more passes: raise MaxPasses.
  • If it oscillates, there is too little redundancy per component: coarsen Pool ("obsType" or "all"), use a smaller Noise.Grid, or smooth the spectrum (Noise.Smooth). A spectrum that keeps moving also points to too few arcs per frequency, or a start far from the data.
  • If one stream stays non-white on every pass, see “Whiteness per stream” above.

7.9.3 Skipped arcs and the warnings inventory

An arc that cannot be used in a pass is skipped and keeps its previous factor. The reason is 'gap' or 'nonPD' (its covariance could not be factored). R.history.skips lists every skip as {pass, arcKey, reason}. A pass that skips more than Noise.SkipThreshold (0.2) of the arcs is refused with lsqvce:adjustVCEjoint:skipThreshold. A few nonPD skips usually mean a Cep or a law that is not positive definite on those arcs, so inspect that day’s buildDay output.

Warnings are raised once per run. Muted or not, every warning identifier the run raised is listed in R.meta.warnings (first-fired order). Check it in batch jobs. The ones that qualify a result:

identifier meaning

7.9.4 Robust runs

A robust run reports ROBUST_FIT at Level 1. Its weights come back in R.noise.robust when the robust pass runs inside the noise loop: influence, scale per stream, factor per epoch in sweep order, keys, and truncation. For the stand-alone IRLS they are in R.noise.influence and R.noise.scale, with per-pass scale, dx, nDown and nZero in R.history. Down-weighted epochs are the robust counterpart of a flag list. Compare them with a Pope or MAD snooping run before you remove anything permanently.

How to read it, in order:

  1. Level 0. Check that [identity holds] is printed and that no [ERROR] appears. If one does, stop: the verdict is INVALID.
  2. Level 1, loop line. If the run iterated, check that the stochastic model settled. If not, every later line is provisional.
  3. Level 1, the ratio. Read the confidence interval on sigma0, not the pass/fail. A ratio well above 1 sends you to Level 2 (outliers) and to R.systematic.
  4. Level 2. Read the scale cross-check before the flag list: if the check reports contamination, the list is not to be believed. With flags, read each w next to its r_i, and reject with R.snoop, one observation at a time.
  5. Level 3. Check that the quadrant table has no UNTESTED or AMBIGUOUS counts and that no uncontrolled or infinite-MDB observations are reported. Check that the external reliability is normal for this n.
  6. Level 4. Check that the conditioning is far from 1e10 and that no correlation is above 0.95. If PAR_SCALE fires, decide which sigma column applies only after Levels 1 and 2 are resolved.
  7. Outside the report. For a noise run, check R.summary() for non-white streams, R.history.skips, and R.meta.warnings.

8 Watching a run

8.1 During the run: OnPass

Options.OnPass is called after every pass of every iterative run (the noise loop, IRLS, Gauss–Newton) with the pass state, the live accumulator, your declaration and your processingOptions. Plot, drawnow, save — or return false to stop after the pass:

function go = myInspect(ctx)
    res = lsqvce.engine.residuals(ctx.acc, struct('x', ctx.x, 'sigma0', ctx.sigma0, ...
              's0sq', ctx.s0sq, 'Cxx', ctx.Cxx), 'Verbose', false);
    figure(1); plot(res.sys(1).obs(1).t, res.sys(1).obs(1).w, '.'); drawnow;
    fprintf('pass %d: largest change %.3g\n', ctx.pass, ctx.maxDev);
end

R = lsqvce.fit(data, Estimate="noise", OnPass=@myInspect);

The fields of ctx are listed in the API reference (lsqvce.Options, OnPass). An error inside the hook stops the run and arrives as lsqvce:callUser:threw with your error as its cause. A stop by the hook is reported as R.stopReason = "userStop", with the last pass returned in full.

Verbose = true prints one progress line per stage; the default is silent. examples/demo_messaging.m shows the output side by side.

8.2 After the run: one figure per question

R.plot("residuals")      % whitened residuals per stream
R.plot("psd")            % the estimated spectra per pool group
R.plot("convergence")    % the components pass by pass
R.plot("contribution")   % which stream determines which parameter

Each call returns one figure handle; nothing is exported by the toolbox. R.stopReason says why the loop ended ("single", "converged", "maxPasses", "userStop", "diverged"), and R.meta.warnings lists every warning identifier the run raised.

8.3 Reproducing a run

R.meta records the toolbox version, the MATLAB release, the creation time, every random seed the run resolved and the options as resolved. Saving R keeps all of them; a run with the same data, options and Seed reproduces the same numbers.

9.5 demo_workflow: build your own case

Purpose. This is the from-scratch recipe for wiring your own data into data, letting lsqvce.fit pick the engine from the shape of the struct, choosing what to estimate, and reading the result in the right order.

Run. demo_workflow is a script with no arguments and no outputs. It runs clear; clc; close all. The help text recommends running it section by section (Ctrl+Enter).

Outline and logic. The script is organised as Sections 0 to 5:

  • Section 0 lists the three kinds of data, which lsqvce.fit tells apart by the fields present:
    • in-memory: A, l, p;
    • batched: batchFcn, numBatches, numUnknowns, or x0 for the nonlinear form;
    • streaming: commonParams, days, systems.
    It also states the batched callback contract [A, l, p] = batchFcn(k), with p the weights 1./sigma.^2. The callback is called twice per batch and must return identical data both times.
  • Section 1 synthesises 3000 observations with 8 unknowns and cuts them into 30 batches with a closure over precomputed batch edges. It sanity-checks batchFcn(1) with an assert and builds data = struct('batchFcn', batchFcn, 'numUnknowns', u, 'numBatches', nb).
  • Section 2 is a decision tree in comments: which kind, and when to use Estimate="noise". It then runs R = lsqvce.fit(data) with default options.
  • Section 2b reads the verdict in a fixed order:
    1. integrity, R.diag.sumRRelErr;
    2. variance, R.diag.varRatio;
    3. blunders, R.diag.nFlag;
    4. reliability.
    The one-line verdict comes from R.report('Verbose', false).verdict.
  • Section 3 is a recipe only, with no runnable code. It shows the streaming declaration with commonParams, scoped localParams and one covariance field per observation type, and points to demo_combine, demo_sensors and demo_grace.
  • Section 4 plants a second instrument group that is three times noisier than claimed. It declares the two groups as two observation types of one streaming system with one day. The inline buildDay returns one arc per group, and the claimed per-row sigmas travel as Cep. Both covariance specs are struct('type','diag','sigma',1,'estimate',"scale"). The run uses Options(Estimate="noise", Pool="stream", ArcFactors=false). The script prints the recovered sigma ratio from Rv.history.sigma(end,:) (the truth is 3) and Rv.sigma0.
  • Section 5 prints the condensed decision tree and the rule for reading a result.

9.6 demo_fit: the three data kinds, one call each

Purpose. This example shows every kind of data that lsqvce.fit accepts, end to end on the user tier: lsqvce.fit, lsqvce.Options, lsqvce.Results and R.report. It also shows robust estimation, a datum declared as a prior, Gauss–Newton through x0, and watching a run with OnPass.

Run.

out = demo_fit();                  % prints the verdicts
out = demo_fit(Verbose=false);     % silent

out has the fields .matrix, .robust, .datum, .batch, .nonlinear, .gls and .vce. Each of them is an lsqvce.Results. out.truth holds the planted values: x = [1; -2; 0.5], [a; b] = [0.7; -0.2], and xGravity of the gravity loader.

Logic.

  1. In-memory. The data are 30 observations with A = [1, randn, randn], seeded with 17, and the call is data = struct('A',A,'l',l,'p',p). The same problem is then run with a 25-sigma gross error at row 7 and Options(Robust="huber"). The demo prints the IRLS weight factor of that row from out.robust.history(end).factor(7).
  2. Free network. The problem has height differences between four points and is rank-deficient by a common level. The datum is declared as data.priors = struct('L', ones(1,4), 'x0', 0, 'sigma', 1). The demo prints L*x. It then removes priors and prints the error identifier with which fit refuses the problem.
  3. Batched, linear. The same 30 rows are split into two batches with struct('batchFcn',bf,'numUnknowns',3,'numBatches',2).
  4. Batched, nonlinear. The model is l = exp(a t) + b. The callback bfn(k, x) returns the Jacobian at x, and data.x0 = [0.5; 0] (the number of unknowns is numel(x0)). The options are Options(MaxPasses=15, Tolerance=1e-9), and the demo prints [a; b].
  5. Streaming. [cfg, data] = demo_gravity_dataLoader() is solved once with defaults (out.gls). It is then solved with Options(Estimate="noise", Pool="stream", ArcFactors=false, MaxPasses=2, OnPass=watch), where watch prints ctx.pass, ctx.maxDev and ctx.sigma after every pass. Two passes are not enough to converge, so the demo suppresses the warning lsqvce:adjustVCEjoint:notConverged. It prints out.vce.history.sigma.

Implementation. The local function show calls R.report('Verbose', true) and prints R.sigma0. According to the help block, the in-memory estimates land within 3 formal sigma, and the nonlinear form recovers [a; b] to 5e-3.

9.7 demo_lsqvce: six failure modes and their verdicts

Purpose. This example teaches you to read the diagnostics. Each of six scenarios isolates one failure, so that you see what R.diag and R.report() say when one specific thing is wrong, and what they say when nothing is.

Run. demo_lsqvce is a script with no arguments. It runs clear; clc. It draws one figure in case 3.

Logic. All cases share a setup of 2000 observations, 8 unknowns and per-row sigma in [0.5, 1.5], seeded with 2026. Each case fits an in-memory struct('A',A,'l',l,'p',p):

  1. Clean: the baseline.
  2. Outliers: three gross errors at rows 137, 892 and 1455. The case prints R2.diag.flagIdx and a note on rejecting only the largest |w| at a time.
  3. Systematic error: an unmodelled 1.2 sin(2 pi t). The case prints nFlag and plots R3.diag.w against time with the ±kCrit lines, above the clean case for comparison.
  4. Uncontrolled observation: unknown 8 is seen only by observation 500. The case prints nFlag and the redundancy number rNum(500).
  5. Wrong weights: group 2 is three times noisier than claimed. The case prints varRatio and nFlag, then shows the cure: a streaming declaration with two observation types g1 and g2 (local helper groupDay) and Estimate="noise", Pool="stream", ArcFactors=false. 9.8 demo_noisePolicy: what you know about each stream

Purpose. This example shows the per-stream policy fields of a covariance spec. estimate is "none", "scale" or "law", and arcFactors is true or false. Each choice recovers a planted truth. For the policy semantics, see the chapter Choosing the stochastic model.

Run.

[R, s] = demo_noisePolicy();
[R, s] = demo_noisePolicy('maxPasses', 20, 'verbose', true);   % defaults: 10, false

R is the lsqvce.Results. s summarises what was measured:

  • .stream, .declared, .level and .truth, per stream;
  • .noneFixed;
  • .rho1: the estimated and planted lag-1 correlation of rr;
  • .arcFactor and .arcRatio;
  • .passes;
  • .badEstimate: the identifier that a misspelt policy raises.

The case. The data have one system, three days and three arcs a day of 256 epochs (5 s), four common harmonic coefficients, and one 'arc'-scoped bias. There are four streams:

Stream Truth Declared Policy
gps white, sigma 0.2 diag, 0.2 (correct) "none"
acc AR(1), phi 0.85, level 0.5 psd of the same filter, sigma 1 "scale"
rr AR(1), phi 0.5 diag, 1 (white) "law"
mag white 0.3, arc 2 three times worse diag, 0.3 "scale", arcFactors = true

Implementation.

  • policyData builds the declaration. For acc it builds a 'psd' law from firstOrderPsd, which gives the one-sided PSD on a frequency grid.
  • policyDay is the six-argument buildDay. It uses info.nl and info.offsetOf(a) to place the bias column, and it returns one cell per arc.
  • policyNoise draws the planted noise from a stream seeded on day and stream, so that buildDay is deterministic.
  • All four policies run in one call with Options(Estimate="noise", Pool="stream", ArcFactors=false, MaxPasses=o.maxPasses, Noise=struct('Smooth', 1)). ArcFactors=false is the run default. mag overrides it on its own spec. The loop converges in 3 passes. Without the smoothing, the 60-bin law of rr needed 14 passes and settled on the same values to three digits.

  • A table of the level per stream (declared, estimated, planted) from R.noise.model{k}.sigma, with streams looked up by name.
  • The lag-1 correlation of rr from R.noise.Cgroups.
  • The mean arc factor per arc of mag from R.noise.model{k}.sigma2, and the ratio of the bad arc to the good arcs (planted: 9).
  • The identifier with which fit refuses estimate = "shape".
  • R.summary().

The help block records the measured values of one run. For example, gps keeps its declared 0.2 exactly, and the bad-arc variance ratio is 9.45 against the planted 9. Only the ratio between arc factors is identifiable, because the level absorbs their mean.

9.9 demo_priors: regularisation in the announced layout

Purpose. In a scoped declaration you do not know in advance which column of A or B an unknown ends up in. lsqvce.layout(data) announces the layout before fit runs, so you can write a prior operator L in those columns. For the full reference, see the chapter Priors and regularisation.

Run.

[R, s] = demo_priors();
[R, s] = demo_priors('verbose', true);

R is the regularised solve. s holds:

  • .nc and .nl;
  • .nullDim;
  • .unregularised: the error identifier;
  • .sigma0 and .zSignal;
  • .nPseudo, .formGap, .datumGap and .priorLevel.

The case. The data have four harmonic signal coefficients ('common') and one offset per day (a 'day' row of commonParams). The system has two 'arc' rows (bias, drift) and one 'system' row (a scale on a known auxiliary series). There are three days with two arcs of 150 epochs each. The day offset and the arc biases cannot be separated, so the normal matrix has one null direction per day.

Logic.

  1. Call lay = lsqvce.layout(data). Print lay.nc, lay.systems(1).nl and the column map from lay.common and lay.systems(1).local, and find the day-offset columns with lay.colCommon(row, day).
  2. Count the null directions on a densely assembled [A B] (rank). Fit without priors and record the refusal identifier.
  3. Declare two common groups in data.priors: a tight 'datum' (the offsets average to zero) and a loose 'smooth' (first differences), both with estimate "none".
  4. Declare a local group 'drift' on data.systems(1).priors, written once through lay.systems(1).col(row, day, arc) and once as the pattern group = '^drift$'. Both solutions are compared.
  5. Move the datum (x0 = 0.5) and measure that the signal stays put while the offsets move.
  6. Run Options(Estimate="noise", Pool="stream", ArcFactors=false, MaxPasses=4) with the drift group at estimate "scale". The group appears as its own stream x1|prior_drift, and its level is printed.

Implementation.

  • priorData builds the declaration.
  • priorDay is the six-argument buildDay. It uses info.commonDayOffset, info.sysOffset and info.offsetOf(a).
  • nullDimension and layoutInfo assemble the dense rank check. That check is for demonstration only; in your own code fit supplies info.
  • fitWithoutGroups gives the pseudo-observation count.
  • R.coefficients().se gives the z-scores of the signal.

9.11 demo_sensors: system / sensor / day, gaps, and a bad day

Purpose. This example declares the full hierarchy:

  • a system is an entry of data.systems;
  • a sensor is an observation type, one field of covariance;
  • a day is an entry of data.days.

It shows a data gap, finds a bad day through one variance factor per sensor-day, and then estimates the per-sensor noise levels without that day. The order is the point: a variance component is an average over its stream, so an event inside the stream corrupts the level.

Run. demo_sensors() takes no arguments and returns nothing.

The case. There are six common unknowns and two systems:

  • GRACE-C (id 'C') carries KBR, LRI and GPS and has 4 locals;
  • GRACE-D (id 'D') carries KBR and LRI and has 3 locals.

The data cover 10 days with 60 observations per sensor and day. The true sigmas are KBR 1.0, LRI 0.4 and GPS 2.5, but every sensor is declared with sigma 1. GRACE-D’s LRI is missing on days 4–5, and GRACE-C’s KBR carries a 6-sigma offset on day 7.

Logic.

  1. Generate the data into a containers.Map per system.
  2. Declare the data. s.arcs is a resolver from makeSchedule that returns no arcs on an outage day, which is how a data gap is declared.
  3. Solve once with Options(Verbose=false) and print R.sigma0 (the symptom).
  4. Find the bad day. Run Options(Estimate="noise", Pool="obsType", ArcFactors=true, MaxPasses=20, Noise=struct('Grid', 8)). Every arc, here one system, sensor and day, gets its own variance factor. The demo looks each factor up by lsqvce.util.arcKey in R.noise.arcKeys and prints it divided by the median of its stream, because the factors are absolute against the claimed sigma 1. An arc above 5 times its stream’s median is marked <<< EVENT.
  5. Remove each event’s arc from the store, so the arc resolver returns no arc for it, as for an outage. Then run Options(Estimate="noise", Pool="obsType", ArcFactors=false, Noise=struct('Grid', 8)). The KBR streams of both systems share one spectral shape, and every stream keeps its own level. The demo prints R.summary().sigma per stream against its truth.

Noise.Grid 8 is used because an arc holds only 60 samples. With the default 60-bin law, the bins that the data barely determine decay toward zero, and the loop needed 168 passes. The help block records the measured values: the event is 15.9 times its stream’s median, every other sensor-day lies between 0.5 and 1.8, and the levels come back within 4.0 % of the truth. Estimated with the event still in the data, C|KBR came back 46 % high.

9.18 bench_qr_vs_normal: which backend, measured on your machine

Purpose. This benchmark measures the cost of Backend="qr" against Backend="normal" on your hardware, and shows when the accuracy of QR is needed.

Run.

bench_qr_vs_normal()                                       % u = [10 30 50 100], n = 1e5, nk = 5000, reps = 3
bench_qr_vs_normal('u', [10 50 100], 'n', 2e5, 'nk', 5000)

There are no outputs; the benchmark prints two tables.

Logic. Both runs use the same batched declaration, struct('batchFcn', src, 'numUnknowns', u, 'numBatches', nb), with Options(Backend="normal") and Options(Backend="qr").

  1. Timing. For each u, the benchmark times both runs, keeping the best of reps repetitions. It prints the times, their ratio, and the relative agreement of R.x. The timed call is the whole fit, including diagnostics, so the difference between the two times is the cost of the backend.
  2. Accuracy against conditioning. With u = 10 and n = 20000, the benchmark makes column 2 nearly collinear with column 1, for eps = 1e-1 … 1e-8. It compares both backends with an SVD reference and prints cond(R.sol.Cxx), which equals cond(N), the two errors, and a verdict. When N is singular in double precision, the normal path refuses with lsqvce:normalEq:notSPD. The benchmark catches that refusal and reports QR as mandatory.

The recipe the benchmark prints: solve once with "normal", read cond(R.sol.Cxx), and switch to "qr" only when that number calls for it. For the backend option itself, see the chapter lsqvce.Options of the API reference.

10 Large problems

A GRACE-FO month at degree 60 has millions of observations, about 3700 common and tens of thousands of local parameters. This chapter lists the settings that decide whether such a run fits in time and memory. The defaults are safe; change them when you have measured.

10.1 Memory

The accumulator holds the reduced common system, nc × nc. Local parameters are eliminated arc by arc and never enter it. The largest transient object is one built day: m × nc doubles per observation type — at degree 60 about 190 MB for a six-hour three-axis arc.

CacheDays (default 1) is the number of built days kept resident per system. An iterative run reads every day twice per pass; CacheDays = Inf builds each day once per run if the calendar fits in memory. A system’s prepareDay result is kept for the current day only, whatever CacheDays: it adds one day’s worth, and runs again whenever a day is rebuilt. If reading the raw files is the expensive part, cache those inside your buildDay closure instead.

10.2 Time

setting effect
Noise.Whitener = "ar" whitens a long arc in O(m·p) instead of the O(m³) of the dense Toeplitz factor, which is formed over the whole arc (m² memory, refused above maxDenseArc = 20 000 epochs); check the AR fit once with lsqvce.engine.checkPSD. It speeds up the SOLVE: under Estimate = "noise" the estimator’s sweep still forms every arc’s covariance densely (m² memory, O(m³) per arc and pass), and the same maxDenseArc refuses a longer arc there — cut long arcs, or estimate the law on a subset and solve the whole with Estimate = "none"
Probes the cost of the redundancy sweep grows linearly with it; 100 is the standard, fewer gives noisier redundancies
Parallel = struct('Mode', "parfor", 'DistributeDays', true) distributes the day loop of the accumulation over workers; the result is bitwise identical to the serial run
MaxPasses, Tolerance the number of passes of an iterative run

10.3 Backend

Backend = "qr" (default) keeps the square-root information form and is the safer choice on ill-conditioned common blocks; "normal" forms the normal equations and is faster on well-conditioned ones. Both give the same numbers to rounding where both work. examples/bench_qr_vs_normal.m measures the trade-off on your machine.

10.4 Before a long run

  1. Run one day with Estimate = "none" and read the report.
  2. Run a few days with Estimate = "noise" and MaxPasses = 3 and look at R.plot("psd") and R.summary().
  3. Fix Seed so the long run is reproducible, and save R with its meta.
