lsqvce.util.verbosity

Message levels and banner formatting, in one place.

Description

The toolbox used a BOOLEAN 'verbose', which forced one decision on two
different audiences: someone watching a long run wants a progress line per
outer pass, while someone debugging a stream that will not whiten wants the
per-stream detail behind it. One flag cannot serve both, so the output was
either too sparse to diagnose or too noisy to watch. This class replaces the
flag with four LEVELS, and owns the banner vocabulary so every line in the
toolbox is laid out the same way.

The Levels

  0  SILENT      nothing at all.
  1  PROGRESS    the shape of the run: outer passes, stage start/done with
                 timings, the convergence verdict. The default, and what you
                 want when watching a long job.
  2  STAGE       adds per-item detail underneath each stage: per-stream AR
                 orders and whiteness, per-group shares, per-day accumulation
                 and residual progress, conditioning in the solve.
  3  DIAGNOSTIC  adds everything the engine can say about WHY: inner VCE
                 iterations, per-stream sigmas, fallbacks taken, numbers that
                 are normally implied rather than printed.

Each level INCLUDES the ones below it, so a check is always "is the current
level at least L", never an equality test. Use the predicates:

  if lsqvce.util.verbosity.atLeast(v, 2), ... end     % explicit
  if lsqvce.util.verbosity.stage(v),      ... end     % same thing, named

BACKWARD COMPATIBILITY (this is why nothing broke)
  Every public 'verbose' option still accepts a LOGICAL, and RESOLVE maps it:
  false -> 0 (SILENT) and true -> 1 (PROGRESS). Those are exactly the two
  behaviours the boolean used to select, so existing calls, tests and demos
  keep their meaning. Levels 2 and 3 are new capability, reachable only by
  passing a number.

THE BANNER VOCABULARY (why it is centralised)

Banners were written by hand at ~30 call sites and had drifted: '[GATE ]'
carried a trailing pad, '[CONTRIB]' was wider than everything around it,
and the same stage appeared as '[SHAPE]' and '[shape   ]'. Misaligned
banners make a log hard to scan, which matters because reading the log is
how defects are caught here (HANDOVER  4d). BANNER enforces one width:

  lsqvce.util.verbosity.banner('SCALE')   -> '[SCALE   ]'
  lsqvce.util.verbosity.banner('shape')   -> '[shape   ]'

CASE IS MEANINGFUL and is preserved, not normalised:
  UPPERCASE  an outer-loop STAGE          [SCALE   ] [SOLVE   ] [GATE    ]
  lowercase  per-item detail under a stage [shape   ] [accum   ] [redund  ]
So the eye can separate "where the loop is" from "what it is doing there"
without reading the words.

Example

  v = lsqvce.util.verbosity.resolve(2);          % or true / false / 0..3
  if lsqvce.util.verbosity.progress(v)
      lsqvce.util.log.msg('%s starting\n', lsqvce.util.verbosity.banner('SCALE'));
  end
  if lsqvce.util.verbosity.stage(v)
      lsqvce.util.log.msg('%s stream %s: AR(%d)\n', ...
          lsqvce.util.verbosity.banner('shape'), key, p);
  end

See also LSQVCE.UTIL.LOG, LSQVCE.ADJUSTVCE
