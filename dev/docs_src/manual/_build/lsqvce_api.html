1 The task definition

Everything the toolbox knows about a problem enters through one object, a lsqvce.TaskDefinition, handed to lsqvce.fit(task, opts). It is filled with flat calls that take name–value arguments; every call checks its arguments when it is made and names the one at fault. Nothing is read before fit runs. help lsqvce.TaskDefinition and doc lsqvce.TaskDefinition show the same contract.

how it is made for
lsqvce.TaskDefinition(Days=days) and its add calls streaming: arc-wise data read day by day through your Build functions, local unknowns eliminated on the fly, estimated stochastic models
lsqvce.TaskDefinition.fromMatrices(A, l, Weights=p) matrices: a design matrix that fits in memory, no local unknowns, diagonal weights
lsqvce.TaskDefinition.fromBatches(@batchFcn, NumBatches=K, NumUnknowns=u) or X0=x0 batched: a design too large for one matrix, or a nonlinear model

One call adds one template per name, all of one scope. A template becomes one parameter per instance of its scope.

name type / size default meaning

scope instantiated as typical use
"common" one column of A, always spherical-harmonic coefficients
"day" (common) one column of A per calendar day that carries at least one arc in at least one system a daily common parameter
"arc" one column of the system’s B per (day, arc) initial state, per-arc empirical parameters; needs an arc schedule

Column layout of A. The "common" templates first, in addCommon order; then one day block per calendar day (the sorted union of every system’s days), holding that day’s "day" commons. Column layout of B (per system). Per day, in calendar order: the arc blocks in sorted arc-id order (each the "arc" templates in addLocal order), then the day block; after all days one trailing "system" block. Your code never computes these positions: Build gives partials by name, or takes columns from ctx.cols.

2 Prepare and Build — the functions you write

Two kinds of function produce the data on demand. Each has one home:

sys = task.addSystem(name, Prepare=@prepare, ...);   % P   = prepare(day, ctx)
sys.addStream(name, Build=@build, Noise=noise, ...);  % out = build(day, ctx)
function runs receives returns
Prepare (optional, per system) once per build of a day, before the first stream of that day the day and a lsqvce.DayContext anything; it reaches every Build of the day as ctx.Prepared
Build (required, per stream) once per build of a day, for its stream the day and a lsqvce.DayContext the lsqvce.DayData of ctx.newDay(), filled with addArc

Both take exactly two arguments. Every pass over the data reads each day twice (accumulation, then the residual sweep), and an iterative run multiplies that by its passes. Hence two rules:

  1. Determinism. The same day must give byte-identical output: no random numbers, clocks or mutable globals (seed a simulator on the day and the stream).
  2. Share the day’s common work through Prepare. The toolbox keeps Options.CacheDays built days resident (default one). Work that several streams of a day need — reading a file, integrating the orbits and their partials — goes into the system’s Prepare, which runs once for all of them each time the day is built.
Prepare rule
how often once each time the day is built: once per run with Options.CacheDays = Inf; with the default CacheDays = 1 a day is built twice per pass, so it runs as often; with Options.Parallel every worker holds its own copy of the loader, so it runs on every worker that builds the day
memory the result of the current day only, whatever CacheDays
refused Settings with a field prepared (lsqvce:makeLoader:preparedField, reported by fit under its own prefix, the original attached as the cause)
when it fails lsqvce:makeLoader:prepareDay names the day; your error is the cause (an lsqvce:* error passes unchanged)

2.2.1 Sigma — the per-epoch accuracy

shape meaning the numbers are
e × 1 scalar stream with per-epoch accuracy standard deviations
e × d multi-axis stream, axes uncorrelated within an epoch standard deviations per axis
e × d × d multi-axis stream, full per-epoch covariance (d ≥ 2) covariance matrices

A scalar stream’s Sigma is always standard deviations. MATLAB stores an e × 1 × 1 array as e × 1, so a per-epoch variance array would be read as sigmas: pass the square root. A full Sigma is composed through its Cholesky factor in the given axis order; when it varies along the arc, the composed covariance therefore depends on the frame and the axis order (XYZ against NEU: about 2 % of C). A constant or diagonal Sigma does not.

The axis count d is size(Sigma, 2), the same for the whole day, and must agree with the stream’s Axes when one above 1 is declared; e·d must equal the arc’s row count. Rows of a multi-axis stream are epoch-major (x₁ y₁ z₁ x₂ …) and every arc holds whole epochs. Sigma is relative to the law’s sigma: declare lsqvce.Noise.white(1) when Sigma already carries the absolute accuracy. A multi-axis day without Sigma is whitened with D = I and reported once per run (lsqvce:makeLoader:noCep); a var law takes no Sigma.

2.3 The arc schedule — Arcs

form meaning

4 or [1 2 4] static: arcs 1…4, or these ids, on every day

3 Noise laws

sys.addStream(name, Noise=n, Estimate=e, ArcFactors=f) declares a stream’s noise in two parts: the temporal law with its level, a lsqvce.Noise object, and what the estimator may change about it, the stream’s Estimate and ArcFactors. The per-epoch accuracy is not declared here: it travels with each arc as Sigma (chapter Prepare and Build). The toolbox composes the covariance of an arc as C = D (R_t ⊗ I_d) D. Full reference: doc lsqvce.Noise, doc lsqvce.engine.covModel.

3.1 Laws

constructor arguments describes whitening cost (b rows per batch, m per arc)
lsqvce.Noise.white(sigma) sigma scalar, or a column of per-row standard deviations white noise O(b)
lsqvce.Noise.arma(ar, sigma, MA=ma) ar = [1 a₁ … a_p], MA (default 1), sigma (innovation std) a known whitening filter O(b·p)
lsqvce.Noise.psd(f, S) f (n_f×1, Hz, one-sided, from 0), S (n_f×1, unit²/Hz) a measured noise spectrum O(m³) per arc (Toeplitz) or O(b·p) (AR filter)
lsqvce.Noise.acf(@rho, sigma) rho(dt, opt), sigma correlation as a function of the lag O(m³) per arc
lsqvce.Noise.var(ar, Sigma) ar (d×d×p), Sigma (d×d) vector AR: cross-axis temporal correlation (no per-arc Sigma) O(b·p·d²)
lsqvce.Noise.custom(@covFcn) covFcn(t, opt) any dense covariance O(m³) per arc

Every constructor takes MaxDenseArc=m (default 20 000 epochs), the longest arc factorised densely. sigma is always a standard deviation, never a variance.

A psd grid starts at f = 0. The autocovariance integrates the piecewise-linear spectrum over the grid only, so a grid that starts higher leaves out the band below its first point. On 512 bins starting at the first nonzero bin, an AR(0.99) law lost 34 % of its variance that way. A grid whose missing band, estimated as f(1)·S(1), exceeds 10⁻⁶ of the variance is refused (lsqvce:psd2acv:noZeroFrequency). The toolbox does not guess the spectrum there: prepend f = 0 with its value, for example [0; f] and [S(1); S] for a flat extension.

3.2 What the estimator may change — on addStream

setting values default meaning under Estimate = "noise"
Estimate "law", "scale", "none" "law"; "scale" for a per-row sigma "law": spectral shape and level are estimated; "scale": the declared shape is kept, only the level is estimated; "none": the stream is used exactly as declared
ArcFactors logical Options.ArcFactors per-arc variance factors for this stream

A per-row sigma column makes the law a fixed structure: it can carry a level but not a spectral shape: its default is "scale", and Estimate = "law" on it is refused (lsqvce:fit:lawOnFixedStructure). A per-arc Sigma does not trigger this — per-epoch accuracy together with an estimated temporal law is the supported combination.

Options.Pool decides which streams share one estimated spectral shape; every stream keeps its own level.

3.3 How a law is whitened

  • Options.Noise.Whitener selects how every psd law whitens — the estimated law and every declared one: "toeplitz" (default, exact), "ar" or "arma" (a fitted filter). Check an AR fit with lsqvce.engine.checkPSD (the relative error of the reproduced autocovariance should be below 1e-3).
  • Filter laws are applied in batches of up to 20 000 rows that overlap by the filter memory (for an MA part, until the impulse response of 1/B(z) has decayed to rounding), so the result does not depend on the batching. Dense laws (acf, custom, Toeplitz psd) are factorised over the whole arc (exact; O(m³), m² memory: 3.2 GB at 20 000 epochs). An arc longer than the law’s MaxDenseArc is refused (lsqvce:covModel:denseArcTooLong): give a psd law a filter (Whitener = "ar"), cut the arcs shorter, or raise MaxDenseArc when the memory is there.
  • An arma law whose MA polynomial has a root on or outside the unit circle is refused (lsqvce:covModel:maNotInvertible). Its exact start-up is a dense block as long as the impulse response of 1/B(z), so MaxDenseArc bounds that too: an MA root close to the unit circle on a long arc is refused (lsqvce:covModel:denseArcTooLong). The same limit bounds the whitener of an arc with many robust nuggets or excluded rows (m·k epoch products for k corrected epochs).
  • Whitener = "arma" reduces the AR fit of the spectrum to an ARMA (Durbin’s method, lsqvce.kernel.ar2arma). A reduction that comes back non-stationary or with a non-invertible MA part falls back to the AR fit, with the warning lsqvce:ar2arma:unstable or lsqvce:ar2arma:nonInvertibleMA.
  • Under Estimate = "law" the declared law contributes only its sigma (the starting level): the shape is estimated from a white start.

4 lsqvce.Options

lsqvce.Options is a typed value class: every knob has a type, a range and a default, checked at assignment (MATLAB:validators:*) or at construction (lsqvce:Options:*). It says how to run; everything about the problem, including regularisation, is declared on the task. Three equivalent spellings:

opts = lsqvce.Options(Estimate="noise", MaxPasses=6);   R = lsqvce.fit(task, opts);
opts.Noise.Grid = 120;                                   % change one later (validated)
R = lsqvce.fit(task, Estimate="noise", MaxPasses=6);     % name-value pairs straight on fit

disp(opts) lists every knob, marking the defaults with *.

4.1 What to estimate

knob values default meaning
Estimate "none", "noise" "none" "none": one generalised least-squares solve under the declared laws. "noise": the joint variance-component estimator — per pool group the spectral shape of the noise, per stream its level, per arc a factor (with ArcFactors), and the σ of every prior group with estimate = "scale".
Pool "stream", "obsType", "all" "stream" which streams share one estimated spectral shape: every (system, type) stream on its own, the streams of one observation type across systems, or all streams of the run. Every stream keeps its own level. The default was "all" until v6.33. Measured: pooling identical spectra gained nothing in x, while pooling different ones failed badly (efficiency 37–132, levels 2–3× off). Pool streams of the same physics deliberately ("obsType").
ArcFactors logical true one variance factor per arc on top of the stream’s level; the factor weights the solve. false: one level per stream. Turn off when arcs are few or short.
Robust "none", "huber", "igg3", "bisquare" "none" M-estimation. With Estimate = "none": stand-alone IRLS on the law-whitened innovations with a MAD scale per pass (budget RobustOpts, factors in R.history(end).factor). With Estimate = "noise": a robust weight per epoch inside the joint estimator, on the residuals descaled by the declared accuracy (budget MaxPasses, factors in R.noise.robust.factor). Prefer "igg3" or "bisquare" for gross blunders.

4.2 The loop

knob values default meaning
MaxPasses integer ≥ 1 10 pass budget of the variance-component loop and of Gauss–Newton (IRLS uses RobustOpts.MaxIter). Exhausting it returns the last pass with R.stopReason = "maxPasses" and one warning.
Tolerance > 0 1e-2 stop rule of the variance-component loop: every arc factor’s change ≤ Tolerance, every spectral bin’s change ≤ Tolerance·max(1, sqrt(200/r)), r its redundancy (at the default a tenth of the bin’s standard error sqrt(2/r) where that is larger); for Gauss–Newton the relative step in units of the formal error
Probes integer ≥ 1 100 Hutchinson probes for the per-lag redundancies of the joint estimator
Seed [] or double [] seed for the probes, recorded in R.meta.seeds

4.3 Run control

knob values default meaning
Backend "qr", "normal" "qr" square-root information (Householder QR) or normal equations (Cholesky); the same numbers to rounding, QR the safer on ill-conditioned common blocks
CacheDays > 0 1 built days kept resident per system; Inf keeps the calendar and builds each day once per run (a built type-day is m × nc doubles); a system’s prepareDay result is the current day’s only, whatever CacheDays

4.3.1 OnPass

The hook receives one struct: driver, pass, x, Cxx, sigma0, s0sq; the loop state (noise loop: S, Sgroups (the bin spectra), C, Cgroups, sigma2, arcKeys, streams, sigma, white, whitePval, maxDev, binRatio, xStep, skips; IRLS: factor, keys, scale, dx; Gauss–Newton: vPv, dxRel, lambda); acc, the live accumulator; data, the compiled declaration (task.declaration() when fit was given a lsqvce.TaskDefinition); processingOptions{k}, system k’s as declared. Return nothing to continue, false to stop after the pass (R.stopReason = "userStop"). An error in the hook arrives as lsqvce:callUser:threw with your error as its cause.

4.4 The groups

A group is a struct; assign a whole or partial struct, or one field. A partial struct is merged onto the defaults; an unknown field is refused (lsqvce:Options:badGroupField).

4.4.1 Noise — the estimated stochastic model

field default meaning

Smooth 1 moving-average half-width on the estimated spectrum, in bins (0 = none). The default 1 (it was 0) was measured better on short and long arcs: x’s variance 1.02–1.11 × an oracle that knows the true covariance (0: 1.10–1.23), formal errors within 6 % of the oracle’s (0: 16–27 % too large), unbiased levels, half the passes

5 Priors

A prior is a group of pseudo-observations L·x = x₀ + v with weight 1/σ², declared on the object whose parameters it constrains:

task.addPrior(name, Name=Value)   % on the common parameters: L in the columns of A
sys.addPrior(name, Name=Value)    % on system sys's local parameters: L in the columns of B

5.1 Settings

name meaning
name the group’s name, unique per owner; a local group becomes the stream prior_<name> of its system
On a regular expression on parameter names. The toolbox builds L: one row per matched name per instance (per day for a "day" template, per arc for an "arc" template, once for "common" / "system")
L the explicit operator (q × nc, or q × nl) in the columns task.layout() announces. Give On or L, never both (lsqvce:TaskDefinition:priorTarget); in-memory tasks take L only
Value a-priori values (q × 1, or a scalar); default 0
Sigma ONE standard deviation for all rows of the group (required); relative weights inside a group go into L
From the pass at which the group becomes active (default 1). A single solve reports a group with From > 1 (lsqvce:fit:priorNotActive) and skips it
Estimate "none" (default): σ fixed; "scale": σ is estimated in every pass of Estimate = "noise" (in a run that cannot estimate it — Estimate = "none", or the in-memory kinds — the group keeps its declared σ, with the warning lsqvce:fit:priorScaleHeld)

A pattern that matches no name, or an L of the wrong width, is refused when fit starts (lsqvce:fit:badPrior).

5.2 Rules

  • Several rows make σ estimable. A group with one row has redundancy ≤ 1: its σ is re-estimated every pass from that one residual (only a group with redundancy r ≤ 0 is left unchanged, flagged in R.noise.priorHistory). Give a "scale" group several rows, or declare it "none".
  • Local rows live in one day. Every row of a local group has its non-zero columns inside one day’s local block or the system block; days are coupled through common parameters only.
  • A datum is a group of its own, or several. Minimum constraints L = Bᵀ on the null space, value 0, give the minimum-constraint solution and covariance for any σ. The datum may be split over groups (translation and rotation declared separately): every group the data cannot see belongs to it, as long as it does not overlap a group the data does see. A group that only partly lies in the null space, or overlaps an information group, is information.
  • Datum rows are not observations. Their redundancy is 0 by construction; the diagnostics keep them in Σr and vPv but do not test or count them (D.nTests, D.datumRows; quadrant "datum" in R.reliability()). A local group’s row counts as a datum row when the data see less than a millionth of it (r ≤ 10⁻⁶).
  • Prior rows are declarations. R.snoop() never rejects a prior row, common or local, and R.systematic() leaves the priors’ rows out of its sequences (D.priorRows).

common groups local groups

6.3 lsqvce.solveContributions — a bootstrap over days

C = R.contributions() streams every day once more and eliminates each day’s own local parameters, so that the day’s reduced normal equations remain. out = lsqvce.solveContributions(C, c) solves any weighted combination of the days:

N* = sum_d c_d N_d,   n* = sum_d c_d n_d,   l'l* = sum_d c_d l'l_d,   dof* = sum_d c_d dof_d

c holds one multiplicity per day of C.days: how often a replicate drew the day (0, 1, 2, …), or any non-negative real for a Bayesian bootstrap. On the QR backend the days’ square-root rows are stacked (times √c_d); the common prior is added once, and the solve is fit’s own. One replicate costs O(D·nc²), independent of how many observations a day held.

output meaning
out.x, out.Cxx, out.sigma0, out.s0sq, out.dof, out.vtv the combination’s solution
out.weights .estimate, .robust, .fixed = true: the weights every day carries
out.locals with 'Locals', true: per drawn day .sysID, .day, .multiplicity, .localIdx, .y, .Cyy

The weights are the run’s final ones, fixed: a noise run’s estimated variance components and a robust run’s hard weights are not re-estimated per combination (a bootstrap of the estimator under fixed weights); a robust run’s σ0 is divided by its truncation factor, as fit’s is. Contributions exist only where the days are separable:

lsqvce:accum:regularisedLocals the accumulation regularised a local block

lsqvce:Results:contributionsNonlinear a Gauss–Newton run (its rows are linearised about x)

7.1 The data struct

7.2 buildDay — the function you write

7.2.1 Signature

fit passes as many of these arguments as the handle declares (nargin); a varargin builder receives all six:

D = buildDay(day, obsType)
D = buildDay(day, obsType, common, local, procOpt)
D = buildDay(day, obsType, common, local, procOpt, info)
argument what it is
day one entry of the system’s calendar (numeric)
obsType one entry of fieldnames(covariance) (char)
common data.commonParams
local this system’s localParams (or {})
procOpt this system’s processingOptions; with a prepareDay, also the field prepared (its result — the name is then reserved)
info this day’s expansion: every column offset of A and B (below); [] when nothing is scoped

fit calls buildDay once per (day, observation type). Every pass over the data reads each day twice (accumulation, then the residual sweep), and an iterative run multiplies that by its passes. Hence two rules:

  1. Determinism. The same arguments must give byte-identical output: no random numbers, clocks or mutable globals.
  2. Share the day’s common work through prepareDay. The toolbox keeps Options.CacheDays built days resident (default one). Work that several observation types of a day need — reading a file, integrating the orbits and their partials — goes into the system’s prepareDay, which runs once for all of them each time the day is built (next section).

7.2.2 Where the handle goes — one per system

buildDay is not an option of fit; it is part of the data. Every entry of data.systems carries its own handle in the field buildDay, next to its own covariance, localParams, days, arcs and processingOptions, and fit calls each system’s handle on that system’s calendar only. lsqvce.Options says how one run proceeds (OnPass among it); the data struct says what is read and by whom.

your situation what to do
several instruments or satellites in one adjustment one entry of data.systems each, each with its own handle; they share only the common parameters
one reader, several setups (data directory, background models, editing thresholds) pass the setup in as data: plain values in processingOptions (the 5th argument), or a closure that binds a configuration object
data sets that do not share common parameters one data struct each, one fit call each 
% two instruments, two readers, one adjustment

% ... or bound by a closure (the examples do this)

A closure declares its own argument count, and that count is what fit passes (nargin, above): declare info when your rows need the column offsets of local or 'day' parameters. What the handle captures must not change during the run — it is called again on every pass (rule 1). It is also the place for a cache of your own that outlives a pass — the raw files of a day, say, when they are smaller than the built rows; what the streams of one day share goes into prepareDay (rule 2). buildDay that is not a function handle is refused before any data is read (lsqvce:fit:builderKind).

7.2.3 What all streams of a day share — prepareDay

buildDay is called once per (day, observation type). When the streams of a day rest on one expensive computation — the reference orbits and the variational partials of both satellites, used by the kinematic orbits and the range-rates — give the system a prepareDay handle. fit calls it once per build of a day, before the first stream of that day is built, and hands its result to every buildDay of that day as procOpt.prepared:

s.prepareDay = @prepareGrace;       % P = prepareGrace(day, common, local, procOpt, info)
s.buildDay   = @buildDayGrace;      % D = buildDayGrace(day, obsType, common, local, procOpt, info)

function P = prepareGrace(day, ~, ~, procOpt, info)
    P.C = integrateWithPartials('C', day, procOpt, info);   % r, v and d[r;v]/dp, whole day
    P.D = integrateWithPartials('D', day, procOpt, info);
end

function D = buildDayGrace(day, obsType, ~, ~, procOpt, info)
    P = procOpt.prepared;               % what prepareGrace returned for this day
    switch obsType
        case 'posC', D = kinematicRows(P.C, day, info);
        case 'posD', D = kinematicRows(P.D, day, info);
        case 'kbr',  D = rangeRateRows(P.C, P.D, day, info);
    end
end

field each cell meaning
A m_a × nc design matrix of the common unknowns
B m_a × nl design matrix of the local unknowns; may be sparse
l m_a × 1 observed minus computed (the reduced observation)
t m_a × 1 epoch of each row in seconds (the whitener needs the lags)

7.2.5.1 Cep — the per-epoch accuracy

shape meaning the numbers are
n_a × 1 scalar stream with per-epoch accuracy standard deviations
n_a × d multi-axis stream, axes uncorrelated within an epoch standard deviations per axis
n_a × d × d multi-axis stream, full per-epoch covariance (d ≥ 2) covariance matrices

A scalar stream’s Cep is always standard deviations. MATLAB stores an n_a × 1 × 1 array as n_a × 1, so a per-epoch variance array would be read as sigmas: pass the square root. A full Cep is composed through its Cholesky factor in the given axis order. When it varies along the arc, the composed covariance therefore depends on the frame and the axis order (XYZ against NEU: about 2 % of C). A constant or diagonal Cep does not.

The axis count d is size(Cep, 2), the same for the whole day; n_a·d must equal the arc’s row count. Rows of a multi-axis stream are epoch-major (x₁ y₁ z₁ x₂ …) and every arc holds whole epochs. Cep is relative to the level sigma of the covariance spec: declare sigma = 1 when Cep already carries the absolute accuracy. A multi-axis day without Cep is whitened with D = I and reported once per run (lsqvce:makeLoader:noCep); a var law takes no Cep.

7.3 Covariance specifications

data.systems(k).covariance.(obsType) is one struct per observation type. Its type selects the temporal law — how the errors of one stream correlate down the epochs — and sigma its level. The per-epoch accuracy is not declared here: it travels with the day as Cep (section buildDay). The toolbox composes the covariance of an arc as C = D (R_t ⊗ I_d) D. Full reference: doc lsqvce.engine.covModel.

7.3.1 Laws

type fields describes whitening cost (b rows per batch, m per arc)
'diag' sigma (scalar, or a vector of per-row standard deviations) white noise O(b)
'arma' ar = [1 a₁ … a_p], ma (default 1), sigma (innovation std) a known whitening filter O(b·p)
'psd' f (n_f×1, Hz, one-sided, from 0), S (n_f×1, unit²/Hz) a measured noise spectrum O(m³) per arc (Toeplitz) or O(b·p) (AR filter)
'acf' acf = @(dt, opt), sigma correlation as a function of the lag O(m³) per arc
'var' ar (d×d×p), sigma (d×d) vector AR: cross-axis temporal correlation (no Cep) O(b·p·d²)
'custom' fcn = @(t, opt) any dense covariance O(m³) per arc

sigma is always a standard deviation, never a variance.

A psd grid starts at f = 0. The autocovariance integrates the piecewise-linear spectrum over the grid only, so a grid that starts higher leaves out the band below its first point. On 512 bins starting at the first nonzero bin, an AR(0.99) law lost 34 % of its variance that way. A grid whose missing band, estimated as f(1)·S(1), exceeds 10⁻⁶ of the variance is refused (lsqvce:psd2acv:noZeroFrequency). The toolbox does not guess the spectrum there: prepend f = 0 with its value, for example [0; f] and [S(1); S] for a flat extension.

7.3.2 Policy fields

field values default meaning under Estimate = "noise"
estimate "law", "scale", "none" "law" "law": spectral shape and level are estimated; "scale": the declared shape is kept, only the level is estimated; "none": the stream is used exactly as declared
arcFactors logical Options.ArcFactors per-arc variance factors for this stream

A per-row sigma vector makes the spec a fixed structure: it can carry a level but not a spectral shape, so estimate = "law" on it is refused (lsqvce:fit:lawOnFixedStructure). A Cep does not trigger this — per-epoch accuracy together with an estimated temporal law is the supported combination.

Options.Pool decides which streams share one estimated spectral shape; every stream keeps its own level.

7.3.3 How a law is whitened

  • Options.Noise.Whitener selects how every psd law whitens — the estimated law and every declared one: "toeplitz" (default, exact), "ar" or "arma" (a fitted filter). Check an AR fit with lsqvce.engine.checkPSD (the relative error of the reproduced autocovariance should be below 1e-3).
  • Filter laws are applied in batches of up to 20 000 rows that overlap by the filter memory (for an MA part, until the impulse response of 1/B(z) has decayed to rounding), so the result does not depend on the batching. Dense laws (acf, custom, Toeplitz psd) are factorised over the whole arc (exact; O(m³), m² memory: 3.2 GB at 20 000 epochs). An arc longer than the spec’s maxDenseArc (default 20 000 epochs) is refused (lsqvce:covModel:denseArcTooLong): give a psd law a filter (Whitener = "ar"), cut the arcs shorter, or raise maxDenseArc when the memory is there.
  • An arma law whose MA polynomial has a root on or outside the unit circle is refused (lsqvce:covModel:maNotInvertible). Its exact start-up is a dense block as long as the impulse response of 1/B(z), so maxDenseArc bounds that too: an MA root close to the unit circle on a long arc is refused (lsqvce:covModel:denseArcTooLong). The same limit bounds the whitener of an arc with many robust nuggets or deleted rows (m·k epoch products for k corrected epochs).
  • Whitener = "arma" reduces the AR fit of the spectrum to an ARMA (Durbin’s method, lsqvce.kernel.ar2arma). A reduction that comes back non-stationary or with a non-invertible MA part falls back to the AR fit, with the warning lsqvce:ar2arma:unstable or lsqvce:ar2arma:nonInvertibleMA.
  • Under estimate = "law" the declared law contributes only its sigma (the starting level): the shape is estimated from a white start.

7.4 Priors

A prior is a group of pseudo-observations L·x = x₀ + v with weight 1/σ², declared in your columns:

data.priors(j)            = struct(...)   % on the common parameters: L in the columns of A
data.systems(k).priors(l) = struct(...)   % on system k's local parameters: L in the columns of B

7.4.1 Fields

field meaning
group a regular expression on the name column of the table (data.paramColumns.name, default column 2). The toolbox builds L: one row per matched template row per instance (per day for a 'day' row, per arc for an 'arc' row, once for 'common' / 'system').
L the explicit operator (q × nc, or q × nl) in the columns lsqvce.layout(data) announces. Give group or L, never both.
x0 a-priori values (q × 1, or a scalar); default 0
sigma ONE standard deviation for all rows of the group; relative weights inside a group go into L
from the pass at which the group becomes active (default 1). A single solve reports a group with from > 1 (lsqvce:fit:priorNotActive) and skips it.
name label (default: the pattern); a local group becomes the stream prior_<name> of its system
estimate "none" (default): σ fixed; "scale": σ is estimated in every pass of Estimate = "noise" (in a run that cannot estimate it — Estimate = "none", or the in-memory kinds — the group keeps its declared σ, with the warning lsqvce:fit:priorScaleHeld)

Malformed fields, or an L of the wrong width, are refused by name (lsqvce:fit:badPrior).

7.4.2 Rules

  • Several rows make σ estimable. A group with one row has redundancy ≤ 1: its σ is re-estimated every pass from that one residual (only a group with redundancy r ≤ 0 is left unchanged, flagged in R.noise.priorHistory). Give a "scale" group several rows, or declare it "none".
  • Local rows live in one day. Every row of a local group has its non-zero columns inside one day’s local block or the system block; days are coupled through common parameters only.
  • A datum is a group of its own, or several. Minimum constraints L = Bᵀ on the null space, x0 = 0, give the minimum-constraint solution and covariance for any σ. The datum may be split over groups (translation and rotation declared separately): every group the data cannot see belongs to it, as long as it does not overlap a group the data does see. A group that only partly lies in the null space, or overlaps an information group, is information.
  • Datum rows are not observations. Their redundancy is 0 by construction; the diagnostics keep them in Σr and vPv but do not test or count them (D.nTests, D.datumRows; quadrant "datum" in R.reliability()). A local group’s row counts as a datum row when the data see less than a millionth of it (r ≤ 10⁻⁶).
  • Prior rows are declarations. R.snoop() never rejects a prior row, common or local, and R.systematic() leaves the priors’ rows out of its sequences (D.priorRows).

7.4.3 Where the result is reported

common groups local groups
σ per pass R.noise.priorHistory R.history.sigma, column satKey|prior_<name>
final σ R.noise.priors (absolute) R.noise.model{k}.sigma of stream satKey|prior_<name>: the factor relative to the group’s declared σ (σ_final = declared σ × this factor)

The rows of every prior enter R.residuals() and the redundancy count.

7.4.4 From a parameter table

A row of a GRAVFIRE-style parameter table carrying {'Tikhonov', fromPass, sigma[, label]} in its 11th column means exactly one such struct; template/gravfire_data.m emits them: rows sharing a label become one group with estimate = "scale", rows without a label one fixed-σ group each.

8.5 lsqvce.DayData

LSQVCE.DAYDATA The arcs one Build returns for one stream and one day.

LSQVCE.DAYDATA  The arcs one Build returns for one stream and one day.

  out = ctx.newDay()                              made by LSQVCE.DAYCONTEXT only
  out.addArc(A, l, t)                             one arc, no local parameters
  out.addArc(A, l, t, Local={names, P; ...})      local partials by name
  out.addArc(A, l, t, B=B)                        local partials as one m x nl matrix
  out.addArc(..., Sigma=s, Excluded=e, Arc=id)

  Build adds the arcs of its day one by one and returns OUT. Every row is
  RAW: observed minus computed, never whitened or scaled by a weight -- the
  toolbox whitens each arc from the stream's LSQVCE.NOISE and its per-epoch
  Sigma, and eliminates the local parameters arc by arc. An arc may be
  empty (0 rows): a data gap.

  LOCAL PARTIALS, ONE OF TWO WAYS PER ARC
    Local={names, P}   P m x numel(names); several rows {names1, P1; names2, P2}.
                       The scope of each name decides its column: this arc's
                       block (Scope="arc"), this day's (Scope="day") or the
                       system's (Scope="system"). The usual way.
    B=B                m x ctx.NumLocal (may be sparse), every column taken from
                       ctx.cols(names, Arc=id) -- for partials that already form
                       one matrix. Never computes an offset by hand.
  Neither: the arc sees no local parameter (B is all zero).

  ARC SCHEDULE. Without a declared schedule (no Arcs on the system or
  stream) the arcs are those added, in order. With one, the arcs are
  ctx.ArcIds: addArc fills them in order, Arc=id places an arc out of
  order, and a scheduled id never added is a data gap.

  INPUT (addArc)
    A         m x nc double      design of the common parameters, nc = ctx.NumCommon,
                                 columns in addCommon order (Scope="day" commons at
                                 ctx.cols(names))
    l         m x 1 double       observed minus computed
    t         m x 1 double       epoch of each row in SECONDS
  NAME-VALUE (addArc)
    Local     n x 2 cell         {names, partials} rows (default: none)
    B         m x nl double      the local design as one matrix (default: none)
    Sigma     e x 1 | e x d | e x d x d double   the per-epoch accuracy: standard
                                 deviations per epoch, per axis, or covariances
                                 (e = m / d epochs); relative to the law's sigma
                                 (default: none, D = I)
    Excluded  m x 1 logical      rows of weight 0, zero in A, B and l, kept for their
                                 index (default: none)
    Arc       scheduled arc id   place this arc (default: the next scheduled one)
  OUTPUT
    out       1x1 lsqvce.DayData   a handle: addArc adds to it

  ACCURACY
    Not applicable: it places given numbers into the engines' arc cells
    without arithmetic. Local= and the equivalent B= give the bitwise same
    fit (test_taskDefinition).

  ERRORS  (raised while the day is read; fit passes them unchanged)
    lsqvce:DayContext:localAndB     one arc gives both Local and B
    lsqvce:DayContext:badLocal      Local is not an n x 2 cell of {names, P} with P
                                    m x numel(names), or names a column twice
    lsqvce:DayContext:badArc        Arc without a schedule, an id the day does not
                                    schedule, an arc added twice, or more arcs than
                                    scheduled
    lsqvce:DayContext:unknownName   a Local name that is not a local parameter of the
                                    system on this day
    lsqvce:DayContext:arcRequired   an arc-scoped Local without a scheduled arc
    lsqvce:makeLoader:*             the engines' checks of the day (row counts,
                                    Sigma shapes), with day and stream named

  EXAMPLE

               Excluded=flagged2);

8.6 lsqvce.fit

LSQVCE.FIT Fit a least-squares adjustment (optionally with VCE) to declared data.

LSQVCE.FIT  Fit a least-squares adjustment (optionally with VCE) to declared data.

  R = lsqvce.fit(task)                        a lsqvce.TaskDefinition (v7, WP-160)
  R = lsqvce.fit(data)                        every default (one GLS solve)
  R = lsqvce.fit(data, opts)                  a lsqvce.Options object
  R = lsqvce.fit(data, Name, Value, ...)      the Options properties, straight on fit
  R = lsqvce.fit(data, opts, Name, Value)     both: the pairs override opts

  THE ONE VERB. You describe the problem with a plain struct `data`
  (the API reference), say what to do with lsqvce.Options, and
  get a lsqvce.Results back:

      R = lsqvce.fit(data, Estimate="noise", Pool="obsType", OnPass=@myInspect);
      R.report;  R.plot("psd");  [C, L] = R.toTable(data);

  THREE DATA KINDS, told apart by the fields of `data`, all on ONE accumulator:
    (A) streaming   data.commonParams, data.days, data.systems(k) with
                    buildDay / covariance / localParams / priors /
                    processingOptions and the optional arc schedule `arcs`
                    (buildDay returns one CELL per arc -- A, B, l, t,
                    Cep as 1 x nArc cells -- and the cells are the schedule
                    unless `arcs` declares one); optional data.priors,
                    data.paramColumns. buildDay is a function handle of
                    each system: several readers in one run are several
                    systems; one reader for several setups takes the setup
                    through processingOptions (its 5th argument) or a
                    closure; data that share no common parameters are
                    separate fit calls. What every stream of a day needs
                    (orbits and partials of a satellite pair) goes in the
                    system's optional prepareDay: called once per build
                    of a day (the current day's result only is kept), its
                    result reaches each buildDay as procOpt.prepared
    (B) in memory   data.A (m x u), data.l (m x 1), optional data.p (m x 1
                    weights); optional data.priors. A FULL m x m SPD weight
                    matrix is kind C's: return it from batchFcn
    (C) batched     data.batchFcn @(k) -> [A, l, p] (or @(k, x) -> [J, w, p] with
                    data.x0 for Gauss-Newton), data.numUnknowns, data.numBatches;
                    optional data.priors
  WHAT RUNS (opts.Estimate / opts.Robust / data.x0):
    Estimate "none"    one generalised solve under the declared laws (adjustBlock)
    Estimate "noise"   the joint variance-component estimator (adjustVCEjoint):
                       one spectral shape per Pool group, one level per stream,
                       per-arc factors when ArcFactors; prior groups with
                       estimate "scale" get their sigma by Helmert / Koch-Kusche,
                       one step per pass from the previous solution, and the
                       loop converges only when that step is below Tolerance too
    Robust "huber" | "igg3" | "bisquare"   IRLS on the same loop: alone it is
                       adjustRobust; with Estimate "noise" the robust pass runs
                       INSIDE the joint loop, R.noise.robust carries
                       the final factors
    data.x0            Gauss-Newton with damping (adjustNonlinear)
  REGULARISATION is declared, never an option: data.priors(j) on the common
  parameters and data.systems(k).priors(l) on the local ones -- one struct per
  group, by `group` (a name pattern) or `L` (in the columns lsqvce.layout
  announces), x0, sigma, from, name, estimate. A free network's datum is the
  prior on its null space.
  WATCHING A RUN: Options.OnPass fires after every pass with the pass state,
  the live accumulator, `data` and every system's processingOptions.

  INPUT
    task   1x1 lsqvce.TaskDefinition   the declaration as flat add-calls; fit
                         compiles it with task.declaration() to the struct below
    data   1x1 struct    the declaration (kind A, B or C as above)
    opts   1x1 lsqvce.Options   default lsqvce.Options()
    Name, Value          any property of lsqvce.Options
  OUTPUT
    R      1x1 lsqvce.Results   x, sigma0, sol (Cxx, dof, vtv), diag, acc, history,
                                noise (S, Sgroups, C, Cgroups, stream, model, priors,
                                checks -- the model checks, WP-154), stopReason,
                                meta (options as resolved, warnings, seeds, version);
                                methods report, summary, convergence, residuals,
                                contribution, contributions, compare, plot,
                                toTable, coefficients, reliability, systematic,
                                snoop, ellipse, redundancy (LSQVCE.RESULTS)

  ACCURACY
    fit adds no arithmetic of its own: the estimate is the block
    accumulator's (LSQVCE.ENGINE.BLOCKACCUMULATOR: the monolithic solve to
    1e-8 relative), the verdict LSQVCE.ENGINE.VERDICT's and the noise
    model LSQVCE.ENGINE.ADJUSTVCEJOINT's -- see theirs. End to end, the
    matrix kind (data.A / .l / .p) reproduces the dense normal equations to
    1e-12 relative (test_fit). WP-138.
    THE FORMAL ERRORS OF AN ESTIMATED NOISE MODEL ARE PLUG-IN (WP-154, M5):
    R.sol.Cxx treats the estimated covariance as known. Measured in the
    review's closed loop (HANDOVER 12.84): their optimism is 3-13 % in sigma
    on short or few arcs (256 epochs, 12 arcs) and ~0 on long records; the

8.7 lsqvce.Options

LSQVCE.OPTIONS The one settings object for LSQVCE.FIT: 12 knobs and 5 groups.

LSQVCE.OPTIONS  The one settings object for LSQVCE.FIT: 12 knobs and 5 groups.

  opts = lsqvce.Options()                       every default
  opts = lsqvce.Options(Name, Value, ...)       override some
  opts.Name = Value                             change one later (validated)
  R = lsqvce.fit(data, Name, Value, ...)        the same names, straight on fit

  WHAT TO ESTIMATE, HOW TO RUN. Everything ABOUT A STREAM (its law, whether
  its law / level / arc factors are estimated) is declared on the stream
  (data.systems(k).covariance.<type>: type, sigma, estimate, arcFactors);
  this object holds only RUN policy: 12 knobs plus five typed groups.

  TOP LEVEL
    Estimate   "none" | "noise"   "none": one GLS solve under the declared
                                  laws. "noise": the joint (Ellmer) variance
                                  component estimator on every stream whose
                                  spec allows it (estimate ~= "none"), with
                                  the policy below
    Pool       "stream" | "obsType" | "all"   which streams SHARE one estimated
                                  spectral shape (every stream keeps its own
                                  level regardless); default "stream" (WP-157,
                                  it was "all"): MEASURED in the review's
                                  closed loop, pooling identical spectra gained
                                  nothing in x (eff 1.00-1.08 pooled, 0.90-1.08
                                  per stream), pooling different ones failed
                                  (eff 37 / 132, levels 2-3 x off); pool streams
                                  of one physics deliberately with "obsType"
    ArcFactors logical            per-arc variance factors on (Ellmer 6.5.4),
                                  default true; false = one level per stream.
                                  The factor is the arc's ABSOLUTE Helmert
                                  factor and weights the solve, so sigma0
                                  settles near 1. TO READ AN ARC'S STANDARD
                                  DEVIATION back, use all three terms:
                                    declared sigma * sqrt(factor) * R.sigma0
    Robust     "none" | "huber" | "igg3" | "bisquare"   IRLS on the same
                                  loop, every kind (details in RobustOpts).
                                  With Estimate "noise" the robust pass runs
                                  INSIDE the joint loop: one residual sweep
                                  per pass, the factors in every arc's
                                  whitener on the next pass; MaxPasses is the
                                  budget, RobustOpts.Tuning the constants
                                  (RobustOpts.MaxIter / Tol belong to the
                                  stand-alone IRLS only)
    MaxPasses  double  10         the pass budget of the variance-component
                                  loop and of Gauss-Newton. IRLS has its OWN
                                  budget, RobustOpts.MaxIter
    Tolerance  double  1e-2       the variance-component loop stops when
                                  every arc factor changed by less than it,
                                  and every spectral bin by less than it
                                  times max(1, sqrt(200/r)), r the bin's
                                  redundancy: at the default a tenth of the
                                  bin's own standard error sqrt(2/r) where
                                  that is larger (WP-147: bins the data
                                  barely determine need no finer step than
                                  their estimate has; R.history.binRatio)
    Backend    "qr" | "normal"    square-root vs normal equations
    Probes     double  100        Hutchinson probes for the per-lag
                                  redundancies; an integer >= 1 (Ellmer's
                                  value is 100). The joint estimator has no
                                  exact route, so 0 is refused
    Seed       [] | double        RNG seed for the probes (recorded)
    CacheDays  double  1          built days kept resident per system; Inf =
                                  the whole calendar (one build per run). A
                                  system's prepareDay result is the current
                                  day's only, whatever CacheDays
    Verbose    logical | 0 | 1    screen messages: 0 silent, 1 progress. The
                                  value is passed to every driver as a flag
                                  (logical(Verbose)), so 2 behaves as 1
    OnPass     [] | @(ctx)        YOUR inspection hook, called at the end of
                                  EVERY pass of every iterative run (the
                                  variance-component loop, IRLS, Gauss-Newton)
                                  with ONE ctx struct: .driver .pass .x .Cxx
                                  .sigma0 .s0sq, the loop state (noise: .S
                                  .Sgroups .C .Cgroups
                                  .sigma2 .arcKeys .streams .sigma .white
                                  .whitePval .maxDev .binRatio .xStep
                                  .skips; IRLS: .factor
                                  .keys .scale .dx; Gauss-Newton: .vPv .dxRel
                                  .lambda), .acc (the LIVE accumulator: call
                                  lsqvce.engine.residuals(ctx.acc, ...) or any
                                  engine function inside the hook), .data (your
                                  declaration as passed to fit) and
                                  .processingOptions (per system, as declared).
                                  Plot, drawnow, save wherever you like; return
                                  nothing to continue, false to stop after this
                                  pass (stopReason "userStop"). A throwing hook
                                  is NOT swallowed (lsqvce:callUser:threw with
                                  your error as cause)

  GROUPS (structs; set fields one at a time or give a whole struct)
    Noise        Grid 60             spectral bins of the estimated law, 0 ..
                                     Nyquist (an integer >= 2); exact at every
                                     lag for any Grid
                 Whitener "toeplitz"|"ar"|"arma"  how a PSD law whitens:
                                                  the estimated law and every
                                                  declared 'psd' law; under
                                                  Estimate "noise" a filter
                                                  speeds up the SOLVE only (the
                                                  sweep forms each arc's law
                                                  densely, maxDenseArc), and
                                                  "ar" approximates the
                                                  estimated shape
                 Smooth 1                         moving average on the PSD,
                                                  half-width in bins (WP-154:
                                                  the default is 1, it was 0)
                                                  -- MEASURED in the review's
                                                  closed loop (256-epoch arcs,
                                                  AR(1) 0.5..0.99, 10 seeds):
                                                  x's variance 1.02-1.11 x the
                                                  oracle's (0: 1.10-1.23), the
                                                  formal sigma 1.00-1.06 x
                                                  (0: 1.16-1.27), the levels
                                                  as unbiased, half the passes;
                                                  2048-epoch arcs unchanged.
                                                  Fewer bins instead (16 / 32)
                                                  biased the level low at high
                                                  phi (-12 % / -5 % at 0.98)
                 FreezeRedundancy 1               components below it hold
                 SkipThreshold 0.2                skip RATE of ONE stream's arcs
                                                  that refuses the pass
    RobustOpts   Tuning [], MaxIter 30, Tol 1e-8
    Diagnostics  Alpha 1e-3, Bonferroni true, Beta 0.2, RMin 0.01, RWeak 0.1,
                 Test "auto"|"pope"|"baarda"|"mad", RobustCheck true,
                 Store "all"|"flagged"|"none", NWorst 1000
    Parallel     Mode "serial"|"parfor"|"spmd", DistributeDays false, Threshold 8
    GaussNewton  TolF 1e-10, Lambda0 1e-6     (x0 problems; MaxPasses / Tolerance
                 are the budget and the step tolerance)

  REGULARISATION is not an option: it is DECLARED on the data, as
  pseudo-observations in the user's own columns -- data.priors(k) on the
  common parameters (L in the columns of A) and data.systems(k).priors(l) on
  the local ones (L in the columns of B), each with x0, sigma, from, group.

  METHODS
    engineArgs(target)   the Name-Value list a driver takes (validated)
    toStruct()           every public property as a struct (provenance)
    disp()               grouped display, engine defaults marked *

  ACCURACY
    Not applicable: a settings object -- typed knobs, their validation at
    assignment and the forwarding of their values to the engine
    (engineArgs); it forms no floating-point result. WP-139.

  ERRORS
    MATLAB:validators:*          a typed property receives a value outside
                                 its type / set / range (at assignment)
    lsqvce:Options:badGrid       Noise.Grid is not an integer >= 2
    lsqvce:Options:badVerbose    Verbose is neither logical nor an integer 0..2
    lsqvce:Options:badOnPass     OnPass is neither [] nor a function handle
    lsqvce:Options:badWhitener   Noise.Whitener is not "toeplitz" | "ar" | "arma"
                                 (any case)
    lsqvce:Options:badGroupField a group struct carries an unknown field
    lsqvce:Options:badTarget     engineArgs target is unknown

  EXAMPLE
    opts = lsqvce.Options(Estimate="noise", Pool="obsType");
    opts.Noise.Grid = 2160;  opts.Parallel.Mode = "parfor";
    R = lsqvce.fit(data, opts);
    % Robust ~= "none" together with Estimate = "noise" runs the robust pass

8.9 lsqvce.report

LSQVCE.REPORT Judge a least-squares adjustment and say so in words.

LSQVCE.REPORT  Judge a least-squares adjustment and say so in words.

  V = LSQVCE.REPORT(D) takes the struct from lsqvce.engine.verdict.diagnose and prints a
  verdict. It returns a struct of machine-readable findings so the same logic
  can drive an automated pipeline.

  The report is ordered so that a failure at one level invalidates the levels
  below it. It refuses to report parameter precision for an adjustment whose
  integrity checks failed, because a sigma computed from a broken system is
  not a conservative estimate -- it is a fabrication.

  LEVELS
    0  INTEGRITY   sum(r) == n-u, vPv >= 0, vPv consistent between passes.
                   These test the CODE, not the data. Failure here means
                   every number below is meaningless.
    1  GLOBAL      variance factor vs chi-square.
    2  LOCALISE    outliers (data snooping), with Bonferroni.
    3  RELIABILITY redundancy numbers, MDB, external reliability.
                   This is the level that says which observations you are
                   NOT ABLE TO CHECK.
    4  PARAMETERS  correlations, conditioning, precision.

  NAME-VALUE
    'Verbose'  true  print the report (default true)
    'Width'    78    line width (>= 40)
    'Provenance' struct()  a run-provenance struct (LSQVCE.RESULTS .meta);
                     when non-empty, ONE level-0 NOTE line
                     (code 'PROVENANCE') states toolbox version, MATLAB
                     release, and creation time. R.report() forwards it
                     automatically; a bare lsqvce.report(D) prints none.
    'Iteration'  struct()  the loop state of an ITERATIVE run:
                     .converged, .stopReason, .nIter and optionally .loop
                     (which loop iterated: 'noise' -- the default, the
                     stochastic model -- 'irls' or 'gaussNewton'; WP-138:
                     a code, it was the display label .what; another value
                     is refused, lsqvce:report:badIteration). When non-empty and the
                     run was not a single solve, ONE level-1 line says
                     whether the stochastic model settled -- 'NOISE_SETTLED'
                     (NOTE) or 'NOISE_UNSETTLED' (WARN). Every number from
                     level 1 down rests on those weights, so a model that was
                     still moving qualifies all of them. R.report() forwards
                     it automatically. An optional .influence (char) names
                     the robust influence of an IRLS run; when non-empty ONE
                     level-1 NOTE ('ROBUST_FIT') says sigma0 and the
                     covariance are those of the reweighted problem.

  OUTPUT V
    V.verdict   'PASS' | 'PASS WITH WARNINGS' | 'SUSPECT' | 'INVALID'
    V.findings  cell array of struct(level, severity, code, msg)
    V.message   the one-paragraph explanation printed under the verdict
    V.nError, V.nWarn, V.nNote
    V.integrityOK  true when every level-0 check held

  INPUT
    D         1x1 struct  diagnostics from LSQVCE.ENGINE.VERDICT.DIAGNOSE
    Name/Value: 'Verbose', 'Width', 'Provenance', 'Iteration' (above).
              The test settings (alpha, rWeak, ...) are not report options:
              they shape D, through lsqvce.Options' Diagnostics group.

  EXAMPLE
      data = struct('batchFcn', src, 'numUnknowns', u, 'numBatches', 4);
      R = lsqvce.fit(data, Verbose=false);
      V = lsqvce.report(R.diag);         % prints the five levels (= R.report)

      % V.verdict    'PASS' | 'PASS WITH WARNINGS' | 'SUSPECT' | 'INVALID'
      % V.findings   machine-readable: {level, severity, code, msg}

      % Drive a pipeline off the codes rather than the text:
      codes = cellfun(@(f) f.code, V.findings, 'UniformOutput', false);
      if ismember('SNOOP_CONTAMINATED', codes)
          error('Pope is blind here -- re-run with Diagnostics.Test = "mad".');
      end

  ACCURACY
    Not applicable to the verdict: it reads D (LSQVCE.ENGINE.VERDICT.DIAGNOSE
    states the accuracy of every number it prints) and forms one band of
    its own, the variance factor's chi2(r) / r at 0.5 % / 99.5 %, by
    LSQVCE.KERNEL.STAT.CHI2INV (|F(x) - p| / p < 1e-11 for r <= 1e7; its
    own ACCURACY). WP-138.

  ERRORS
    lsqvce:report:badIteration  Iteration.loop names no loop the report
                                knows ('noise', 'irls', 'gaussNewton'), or
                                Iteration carries the retired .what

  See also LSQVCE.ENGINE.VERDICT.DIAGNOSE, LSQVCE.ENGINE.VERDICT.SYSTEMATIC.

8.10 lsqvce.layout

LSQVCE.LAYOUT The column layout fit will use – so you can declare priors in it.

LSQVCE.LAYOUT  The column layout fit will use -- so you can declare priors in it.
  lay = lsqvce.layout(data)

  The toolbox derives from your parameter tables (scope tokens, calendar,
  arcs, validity) which column of A and of every system's B belongs to
  which instantiated parameter. This function announces that layout BEFORE
  fit runs, so that data.priors(j).L (columns of A) and
  data.systems(k).priors(l).L (columns of B) can be written in it -- the
  only knowledge the user's regularisation and the toolbox share.

  lay = lsqvce.layout(task)   a lsqvce.TaskDefinition: the same layout, plus
                              .common(j).name, .systems(k).name and
                              .systems(k).local(c).name

                            1x1 lsqvce.TaskDefinition

    .nc            1x1        columns of A
    .common        nc x 1 struct (.row .day)      the template row and (for 'day' rows) the day of every column of A

8.11 lsqvce.solveContributions

LSQVCE.SOLVECONTRIBUTIONS Solve a weighted combination of a run’s days without re-reading them.

LSQVCE.SOLVECONTRIBUTIONS  Solve a weighted combination of a run's days without re-reading them.

  out = LSQVCE.SOLVECONTRIBUTIONS(C, c)
  out = LSQVCE.SOLVECONTRIBUTIONS(C, c, 'Locals', true)

  For a bootstrap over days (WP-158, issue #183). C = R.contributions()
  holds every (system, day)'s reduced contribution of a fit; c gives each
  day a multiplicity -- how often a replicate drew it (0, 1, 2, ...), or any
  non-negative real for a Bayesian bootstrap. The combination's reduced
  normal equations are the weighted sum of the days',
      N* = sum_d c_d N_d,  n* = sum_d c_d n_d,  l'l* = sum_d c_d l'l_d,
      dof* = sum_d c_d dof_d,
  formed on the square root (each day's rows times sqrt(c_d)) on the QR
  backend, and solved exactly as fit solves its accumulation: the common
  prior added ONCE, the same rank rule and cancellation guards. A day drawn
  twice contributes 2 N_d -- no relabelling around lsqvce:fit:duplicateDay.
  One replicate costs O(D nc^2) for D days and nc common parameters,
  independent of the number of observations per day.

  THE WEIGHTS ARE FIXED. Every day carries the run's final weights: a noise
  run's estimated variance components and a robust run's final (hard)
  weights are NOT re-estimated per combination -- a bootstrap of the
  estimator under fixed weights. out.weights says which weights those
  were. A bootstrap that re-estimates them needs a full fit per replicate.
  A robust run's sigma0 is divided by its truncation factor tau (C.truncation)
  as fit's hard solution is: every combination of days is a sample of kept
  epochs truncated alike.

  INPUT
    C   1x1 struct   R.contributions() of a linear fit
    c   1 x D double multiplicity per day, aligned to C.days; finite, >= 0,
                     at least one day > 0

  OPTIONS (Name/Value)
    'Locals'  logical  also back-substitute the local parameters of every
                       day drawn (c_d > 0), with their covariance (default false)

  OUTPUT
    out.x       nc x 1   the common parameters
    out.Cxx     nc x nc  their covariance (s0sq times the cofactor)
    out.sigma0  1x1      sqrt(s0sq);  out.s0sq, out.dof, out.vtv as fit's solve
    out.weights 1x1      C.weights: .estimate, .robust, .fixed = true
    out.locals  struct array, with 'Locals' true, one per system and drawn
                day: .sysID, .day, .multiplicity, .localIdx (the system's
                local indices), .y, .Cyy; [] otherwise

  EXAMPLE
    R = lsqvce.fit(data, opts);
    C = R.contributions();                       % one data pass
    D = numel(C.days);  B = 100;  X = zeros(numel(R.x), B);
    for b = 1:B
        draw = randi(D, 1, D);                   % D days with replacement
        c = accumarray(draw(:), 1, [D 1]).';
        X(:, b) = lsqvce.solveContributions(C, c).x;
    end
    Cboot = cov(X.');                            % the bootstrap covariance of x

  ACCURACY
    With every multiplicity 1 the combination reproduces fit's x, Cxx and
    sigma0 on the QR backend to 1e-8 relative, the issue's acceptance
    bound (measured 2e-10 in x and Cxx, 2e-14 in sigma0 at cond(A) ~ 9e4:
    the days' reduced rows are stacked and re-factorised where fit stacked
    each system's); with a multiplicity vector it equals a full fit over the
    expanded day list (a day drawn twice entered twice, under the same
    fixed weights) to 1e-8 (measured 9e-10); the locals of a drawn day equal
    fit's back-substitution to 1e-8 (measured 2e-10); a noise run and a
    robust run (sigma0 with tau) reproduce their fit alike (test_fit
    (testContributionsReproduceTheFit, testContributionsEqualAFitOverTheExpandedDays,
    testContributionsReturnTheDrawnDaysLocals, testContributionsOfANoiseAndARobustRun)).
    On the normal backend the agreement is that of the normal equations
    themselves, cond(N) eps: at cond(N) ~ 7e9 fit's own normal solve is
    5e-4 from the QR one (testContributionsOnTheNormalBackend uses a
    well-conditioned fixture).

  ERRORS
    lsqvce:solveContributions:badContributions  C is not R.contributions()'s struct
    lsqvce:solveContributions:badMultiplicity   c is not 1 x numel(C.days), finite,
                                                >= 0 with one day > 0
    (and the solve's own: lsqvce:accum:priorNotPD, lsqvce:qr:*)

  See also LSQVCE.FIT, LSQVCE.RESULTS
